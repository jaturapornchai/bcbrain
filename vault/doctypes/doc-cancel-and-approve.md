# กลไกการยกเลิกเอกสาร การยกเลิกรายบรรทัด และการกลับรายการ GL

BC Ai Account ออกแบบการยกเลิกและอนุมัติเอกสารตามมาตรฐาน Audit Trail ของ BC 5.5 คือ **ไม่ลบเอกสารต้นฉบับออกจากฐานข้อมูลเมื่อใช้เมนูยกเลิก** แต่จะสร้าง **"เอกสารใบยกเลิก" (Cancel Document)** ที่มี `trans_flag` เฉพาะของตัวเอง (เช่น ยกเลิกขายใช้ `trans_flag = 45` ฟอร์แมต `SIC`) อ้างอิงกลับไปยังเอกสารต้นฉบับผ่าน `doc_ref = orig_doc_no` (ดูรหัสคู่ยกเลิกทั้งหมดใน [[doc-trans-flag-catalog]])

---

## 1. รูปแบบการยกเลิก 2 โหมด (`cancel_type`)

ใน `doc_cancel.go` ระบบแบ่งพฤติกรรมการยกเลิกออกเป็น 2 โหมด:

### โหมด 1: ยกเลิกทั้งใบ (`cancel_type = 0` หรือ `1` — ค่ามาตรฐานของทุกหน้าจอ)
เมื่อบันทึกใบยกเลิก (เช่น `45` ยกเลิกใบขาย `44`, `13` ยกเลิกใบซื้อ `12`, `240` ยกเลิกใบเสร็จ `239`, `23` ยกเลิกใบจ่ายชำระ `19`):
1. สร้างหัวเอกสารใบยกเลิกในตารางเดียวกับเอกสารต้นฉบับ (`ic_trans` หรือ `ap_ar_trans`) โดยใส่ `doc_ref = เลขที่เอกสารเดิม`
2. อัปเดตเอกสารต้นฉบับให้ **`last_status = 1`** ครบทุกตารางที่เกี่ยวข้อง:
   - หัวเอกสาร (`ic_trans.last_status = 1` หรือ `ap_ar_trans.last_status = 1`)
   - รายการบรรทัด (`ic_trans_detail.last_status = 1` หรือ `ap_ar_trans_detail.last_status = 1`)
   - การรับ-จ่ายเงิน (`cb_trans.last_status = 1`, `cb_trans.status = 1`, `cb_trans_detail.last_status = 1`)
   - ทะเบียนเช็ค/บัตรเครดิต: ลบหรือคืนสถานะเช็คที่เกิดจากเอกสารนั้นตามกติกาใน [[doc-impact-cash-bank-cheque]]
3. **ผลต่อรายงานภาษีมูลค่าเพิ่ม (`gl_journal_vat_buy` / `gl_journal_vat_sale`)**: แถวใบกำกับภาษีเดิม **ยังคงอยู่ในตาราง** เพื่อให้แสดงคำว่า `"ยกเลิก"` ในรายงานภาษีขาย/ภาษีซื้อตามข้อกำหนดกรมสรรพากร แต่ Query รายงานจะแสดงยอดเงินเป็น `0.00` เมื่อพบว่าเอกสารต้นฉบับมี `last_status = 1` (ดู SQL จริงใน [[sql-tax-vat-buy-sale-pp30]])
4. **ผลต่อบัญชีแยกประเภท (`reverseCancelledGL`)**: สร้างรายการกลับบัญชี Dr ↔ Cr ด้วยเลขที่ใบยกเลิก (รายละเอียดในหัวข้อที่ 3)
5. คำนวณสถานะเอกสารต้นน้ำใหม่ (`recomputeDocStatus`) เพื่อปลดล็อกเอกสารต้นทาง (เช่น ปลดล็อกใบสั่งขาย `36` หรือใบวางบิล `235` ให้กลับมาใช้ใหม่ได้)

### โหมด 2: ยกเลิกรายบรรทัด / ยกเลิกจำนวนค้างส่ง (`cancel_type = 2`)
รองรับเฉพาะใบยกเลิกของเอกสารสั่งซื้อ/สั่งขาย/เสนอราคา/สั่งจอง **5 รหัสเท่านั้น**:
- `3` (`PRC` — ยกเลิกใบเสนอซื้อ `2`)
- `7` (`POC` — ยกเลิกใบสั่งซื้อ `6`)
- `31` (`SOC` — ยกเลิกใบเสนอราคาขาย `30`)
- `37` (`SSC` — ยกเลิกใบสั่งขาย `36`)
- `39` (`SRC` — ยกเลิกใบสั่งจอง `34`)

**ความแตกต่างสำคัญของ `cancel_type = 2`**:
- เอกสารต้นฉบับ (เช่น `PO` หรือ `SO`) **ยังคงมี `last_status = 0`** (ไม่ถูกยกเลิกทั้งใบ!) เพื่อให้บรรทัดที่ส่งของไปแล้วไม่เสียประวัติ
- ระบบจะคัดลอกเฉพาะบรรทัดและจำนวน (`qty`) ที่ต้องการตัดยอดค้างส่งลงใน `ic_trans_detail` ของใบยกเลิก (`trans_flag IN (3, 7, 31, 37, 39)`) โดยชี้ `ref_doc_no = orig_doc_no`
- เมื่อคำนวณยอดค้างรับ/ค้างส่งและ `doc_success` ระบบจะนำ `qty` ที่ส่งจริง **บวก** `qty` ในใบยกเลิกรายบรรทัดเหล่านี้ เพื่อปิดใบสั่งซื้อ/สั่งขายเป็น `doc_success = 1`

## 2. กฎป้องกันการยกเลิก/ลบเอกสารที่ถูกอ้างอิงแล้ว (`refuseIfReferenced`)

ก่อนอนุญาตให้แก้ไข ลบ หรือยกเลิกเอกสาร ระบบจะตรวจสอบความถูกต้องของสายโซ่เอกสารเสมอ:
1. **งวดบัญชีปิดแล้ว (`checkOpenPeriod`)**: หาก `doc_date` อยู่ในงวดบัญชีที่ปิดแล้ว ระบบจะปฏิเสธทันที
2. **เอกสารถูกดึงไปอ้างอิงต่อแล้ว**:
   - ห้ามยกเลิก `PR (2)` / `PO (6)` / `QT (30)` / `SR (34)` / `SO (36)` แบบทั้งใบ หากมีเอกสารปลายน้ำที่ยังไม่ยกเลิกอ้างอิงอยู่ (ต้องยกเลิกปลายน้ำก่อน หรือใช้ `cancel_type = 2` ตัดเฉพาะยอดคงเหลือ)
   - ห้ามยกเลิกหรือแก้ไขบิลซื้อ/ขาย (`12, 315, 44, 46, 48, 87..103, 1802`) หากถูกดึงไปทำใบวางบิล (`213, 235`) หรือรับ/จ่ายชำระหนี้ (`19, 239`) ที่ยังมี `last_status = 0`
   - ห้ามยกเลิกใบรับเงินมัดจำ/จ่ายเงินมัดจำ (`10, 11, 40, 110`) หากถูกนำไปตัดใช้ใน `cb_trans_detail` (`doc_type IN (5, 6)`) หรือทำรับคืน/จ่ายคืนไปแล้ว
   - ห้ามยกเลิก แก้ไข หรือลบเอกสารที่มีเช็ครับ/เช็คจ่ายหรือบัตรเครดิตซึ่งถูกนำไปฝาก ผ่าน คืน เปลี่ยน หรือขึ้นเงินแล้ว (`refuseUsedCheque` และ `refuseUsedChequeCancel` ใน `doc_cancel.go:190, 822-863` รวมถึงการตรวจใน `docs.go:632` และ `trans.go:579, 700` โดยเช็กทั้ง `cb_chq_list.status <> 0` และรายการเคลื่อนไหวใน `ic_trans_detail` `trans_flag IN (410,411,412,413,414,416,418,451,452,453,456,461,462,463)` รวมถึง `referencingDocSQL` ใน `doc_cancel.go:679-711` ที่ตรวจเชื่อมโยง `cb_chq_list` ด้วย)

## 3. การกลับรายการบัญชีแยกประเภทเมื่อยกเลิก (`reverseCancelledGL`)

เมื่อบันทึกใบยกเลิกทั้งใบ (เช่น `SIC` เลขที่ `SIC-000001` ยกเลิกใบขาย `SI-6911-0001`):
- บัญชีแยกประเภท (`gl_journal` / `gl_journal_detail`) ของใบเดิม `SI-6911-0001` ในวันที่เดิม **ยังคงอยู่** (เพื่อรักษาร่องรอยตามวันที่เกิดรายการ)
- ฟังก์ชัน `reverseCancelledGL` (`doc_cancel.go:733-825`) จะอ่านบรรทัด `gl_journal_detail` ทั้งหมดของเอกสารต้นฉบับ แล้วสร้างใบสำคัญใหม่ในชื่อเลขที่ใบยกเลิก (`SIC-000001`) ณ วันที่ยกเลิก โดย **สลับยอด `debit` เป็น `credit` และ `credit` เป็น `debit` ทุกบรรทัด** พร้อมตั้ง `trans_flag` เป็นรหัสใบยกเลิก (เช่น `45`) และคืนทั้งจำนวนใบสำคัญ (`journals`) และบรรทัด (`lines`) เพื่อนับรวมเข้า `DocsProcessed` / `LinesCreated` ใน `rebuildGLTx` (`service.go:2511-2519`)
- หากลบใบยกเลิกออกจากระบบ (Undo Cancel): ระบบจะลบใบสำคัญของใบยกเลิกออก และคืนค่า `last_status = 0` ให้เอกสารต้นฉบับกลับมาทำงานตามปกติ ทั้งนี้ `cancelDocTx` (`doc_cancel.go:211-227, 866-926`) จะตรวจซ้ำก่อนคืนสถานะเสมอ ได้แก่ `billSaveCheck` (สำหรับเอกสารวางบิลใน `ap_ar_trans`) และ `checkUndoDepositUse` (สำหรับเอกสารที่ใช้มัดจำ/ล่วงหน้าใน `cb_trans_detail` `doc_type IN (5, 6)` หรือใบคืนมัดจำ `20, 25, 42, 112`) เพื่อป้องกันการคืนสถานะที่ทำให้ยอดมัดจำหรือบิลติดลบ/ตัดซ้ำ

> **ข้อควรระวังในการเขียน SQL ฝั่ง `gl_journal`**:
> - ถ้ายกเลิกผ่านเมนู "ยกเลิกเอกสาร" (มีใบยกเลิกคู่กัน เช่น `44` คู่ `45`) ทั้งใบเดิมและใบยกเลิกจะหักล้าง Dr/Cr กันเป็นศูนย์ใน `gl_journal_detail`
> - แต่ถ้าบางฐานข้อมูลมีเอกสารที่ถูกตั้ง `last_status = 1` โดยไม่มีใบกลับรายการ (เช่น ข้อมูลนำเข้าเก่า) การเช็ก Cashflow หรือ Tax Tie-out ที่ต้องการความแม่นยำสูงสุดจะกรอง `NOT EXISTS (SELECT 1 FROM ic_trans t WHERE t.doc_no = h.doc_no AND t.trans_flag = h.trans_flag AND COALESCE(t.last_status, 0) <> 0)` ร่วมกับเช็กว่าไม่มีใบยกเลิกคู่กัน (ดูตัวอย่างใน [[sql-tax-health-and-pnd50]])

## 4. กลไกเอกสารอนุมัติ (`PRA`, `POA`, `SOA`, `SRA`, `SSA`)

เอกสารอนุมัติ (`trans_flag` `4, 8, 32, 38, 52`) เก็บในตาราง `ic_trans` โดยมี `doc_ref` ชี้ไปยังเอกสารรออนุมัติ (`2, 6, 30, 34, 36`):
- ไม่กระทบสต็อก (`calc_flag = 0`), ไม่สร้างภาษี และไม่โพสต์ GL
- อัปเดตคอลัมน์ `approve_status` บนหัวเอกสารต้นฉบับ (`1` = อนุมัติ, `2` = ไม่อนุมัติ) เพื่อให้หน้าจอดึงเอกสารไปเปิด PO / SO / Invoice กรองเฉพาะใบที่ผ่านการอนุมัติแล้วได้
