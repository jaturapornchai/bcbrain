# ผังบัญชีมาตรฐาน TFRS (`gl_chart_of_account`) และรหัสบัญชี `XXXX-XX` ครบ 5 หมวด

BC Ai Account มาพร้อมชุดผังบัญชีมาตรฐานไทยตามมาตรฐานการรายงานทางการเงิน (TFRS) ในรูปแบบรหัส `XXXX-XX` (`coa_presets.go:defaultStandardChartOfAccounts`) ซึ่งสอดคล้อง 100% กับแม่แบบผูกบัญชีอัตโนมัติใน [[doc-gl-templates-trade-apar]] และ [[doc-gl-templates-cb-ic-fa]]

## 1. ความหมายคอลัมน์ควบคุมในตาราง `gl_chart_of_account`

| คอลัมน์ | ค่าที่เป็นไปได้และความหมายจริงในโค้ด |
|---|---|
| **`code`** | รหัสผังบัญชี (เช่น `1111-00`, `2121-00`) — เป็นคีย์เชื่อมกับ `gl_journal_detail.account_code` |
| **`main_code`** | รหัสบัญชีคุมระดับแม่ (เช่น `1111-01` ชี้ `main_code = '1111-00'` และ `1111-00` ชี้ `main_code = '1000-00'`) ใช้สร้าง Tree งบทดลองและงบการเงิน |
| **`account_level`** | ระดับชั้นของผังบัญชี (`0` = หมวดใหญ่สุด, `1` = บัญชีระดับ 1, `2` = บัญชีย่อยระดับ 2) |
| **`account_type`** | **หมวดบัญชีหลัก 5 หมวด**:<br>• `0` = สินทรัพย์ (Assets)<br>• `1` = หนี้สิน (Liabilities)<br>• `2` = ส่วนของผู้ถือหุ้น / ทุน (Shareholders' Equity)<br>• `3` = รายได้ (Revenues)<br>• `4` = ค่าใช้จ่าย (Expenses) |
| **`status`** | `0` = บัญชีย่อยที่ลงรายการได้จริง (Postable Sub-account)<br>`1` = บัญชีคุมยอด (Control Account — ห้ามโพสต์รายการตรง ใช้รวมยอดจากลูกเท่านั้น) |
| **`balance_mode`** | ธรรมชาติฝั่งดุลปกติ: `0` = เดบิต (Dr), `1` = เครดิต (Cr) (สังเกตว่าบัญชีปรับมูลค่า เช่น ค่าเสื่อมสะสม `1219-01` อยู่หมวด `0` สินทรัพย์ แต่มี `balance_mode = 1` เครดิต และรับคืนขาย `4120-00` อยู่หมวด `3` รายได้ แต่มี `balance_mode = 0` เดบิต) |
| **`tax_type`** | `0` = ไม่เกี่ยวกับภาษี, `1` = ภาษีขาย, `2` = ภาษีซื้อ, `3` = ภาษีหัก ณ ที่จ่ายค้างจ่าย, `4` = ภาษีถูกหัก ณ ที่จ่าย |
| **`balance_sheet_status`** | `0` = ทั่วไป, `1` = ต้นทุนขาย, `2` = ต้นทุนการผลิต, `3` = ค่าใช้จ่ายขายและบริหาร, `4` = กำไร(ขาดทุน)สะสม |
| **`account_close`** | รหัสบัญชีกำไรสะสมปลายทางเมื่อสั่งประมวลผลปิดบัญชีสิ้นปี (หมวด `3` และ `4` ชี้ไปที่ `3210-00`) |

## 3. การปรับตัวเข้ากับผังบัญชีที่ลูกค้ากำหนดเอง (Custom COA Resolution)

สำหรับฐานข้อมูลลูกค้าเดิมที่ไม่ได้ใช้รหัส `XXXX-XX` (เช่น ใช้รหัส 5–6 หลัก `11101`, `41001`):
- ฟังก์ชัน `ensureStandardCoaAndLoadNames` (`coa_presets.go:149-199`) จะตรวจรูปแบบรหัสใน `gl_chart_of_account` ก่อน หากบริษัทใช้รหัสเฉพาะของตนเอง ระบบจะไม่เขียนทับผังบัญชีเดิม
- ฟังก์ชัน `resolveChartAccount`, `resolveInputVatAccount`, `resolveOutputVatAccount` (`service.go:1806-1883`) จะค้นหาจาก `tax_type`, รหัสนำหน้า (Prefix) และชื่อบัญชีตามลำดับ เพื่อให้ลงบัญชีได้แม่นยำไม่ว่าจะใช้ผังบัญชีรูปแบบใด
