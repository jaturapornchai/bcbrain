# ผลกระทบเอกสารต่อภาษีซื้อ-ภาษีขาย (VAT) ภาษีบริการ ม.78/1 และหัก ณ ที่จ่าย (WHT)

เมื่อบันทึกเอกสารที่มีภาษีมูลค่าเพิ่มหรือภาษีหัก ณ ที่จ่าย ระบบจะสร้างแถวในตารางทะเบียนภาษีโดยอัตโนมัติ (หรือรับค่าที่ผู้ใช้แก้ไขบนแท็บภาษีเมื่อตั้ง `is_manual_vat = 1`) ดูตัวอย่าง SQL รายงานภาษีครบชุดได้ที่ [[sql-tax-vat-buy-sale-pp30]], [[sql-tax-wht-pnd-register]] และ [[sql-tax-health-and-pnd50]]

---

## 1. ความแตกต่างชื่อคอลัมน์ระหว่าง `gl_journal_vat_buy` และ `gl_journal_vat_sale`

จุดที่นักพัฒนาเขียน SQL ผิดบ่อยที่สุดคือ **ตารางภาษีซื้อและตารางภาษีขายใช้ชื่อคอลัมน์ฐานภาษีและยอดภาษีต่างกัน** ตามโครงสร้างดั้งเดิมของ BC 5.5 (`journaltax.go:154-178`, `report_menu_gl_fa.go:1044-1150`):

| ความหมายของข้อมูล | ตารางภาษีซื้อ `gl_journal_vat_buy` | ตารางภาษีขาย `gl_journal_vat_sale` |
|---|---|---|
| เลขที่เอกสารระบบ / รหัสเอกสาร | `doc_no`, `trans_flag` | `doc_no`, `trans_flag` |
| เลขที่ใบกำกับภาษี / วันที่ใบกำกับภาษี | `vat_doc_no`, `vat_date` | `vat_doc_no`, `vat_date` |
| รหัสคู่ค้า / ชื่อในรายงานภาษี | `ap_code`, `ap_name` | `ar_code`, `ar_name` |
| เลขประจำตัวผู้เสียภาษี / สาขา | `tax_id`, `branch_type`, `branch_code` | `tax_id`, `branch_type`, `branch_code` |
| ปีภาษี / เดือนภาษีที่ยื่น ภ.พ.30 | `vat_effective_year`, `vat_effective_period` | `vat_effective_year`, `vat_effective_period` |
| **มูลค่าฐานภาษี (ก่อน VAT)** | **`base_amount`** (`NUMERIC`) | **`except_amount_1`** (หรือ **`base_caltax`** ตามเวอร์ชันตาราง; ใน `vatInsertSQL` ใช้คอลัมน์ฐานภาษีขายคู่กับ `amount`) |
| **จำนวนเงินภาษีมูลค่าเพิ่ม (VAT)** | **`vat_amount`** (`NUMERIC`) | **`amount`** (`NUMERIC`) |
| **มูลค่ายกเว้นภาษี / นอกขอบเขต** | **`except_vat`** (`NUMERIC`) | **`except_amount_2`** / **`except_vat`** |
| ตัวคูณเครื่องหมาย (`+1` เพิ่ม, `-1` ลดหนี้) | `vat_calc` (`1` ปกติ, `-1` ลดหนี้ซื้อ `16,25,91,262,317`) | `vat_calc` (`1` ปกติ, `-1` ลดหนี้ขาย `48,103,112,252`) |
| ประเภทรายการภาษี (`vat_type`) | `0`=ขอคืนได้ปกติ, `1`=ขอคืนไม่ได้/เฉลี่ย, **`2`=ภาษีซื้อยังไม่ถึงกำหนด** | `0`=ภาษีขายปกติ, **`1`=ภาษีขายยังไม่ถึงกำหนด** |
| เลขที่เอกสารอ้างอิงเมื่อกลับรายการภาษีพัก | `ref_doc_no` | `ref_doc_no` |

> **เคล็ดลับเรื่องปีภาษี (`vat_effective_year`)**: ในฐานข้อมูลจริงอาจเก็บทั้งปี พ.ศ. (`> 2400` เช่น `2569`) หรือปี ค.ศ. (`2026`) ดังนั้นการกรองงวดภาษีใน SQL ต้องแปลงเป็น ค.ศ. ก่อนเสมอ:
> `((CASE WHEN COALESCE(v.vat_effective_year, 0) > 2400 THEN v.vat_effective_year - 543 ELSE COALESCE(v.vat_effective_year, 0) END) * 100 + COALESCE(v.vat_effective_period, 0))`

## 3. วงจรภาษีมูลค่าเพิ่มยังไม่ถึงกำหนด (ธุรกิจบริการ มาตรา 78/1)

ตามประมวลรัษฎากร มาตรา 78/1 ความรับผิดในการเสียภาษีมูลค่าเพิ่มของการให้บริการเกิดขึ้นเมื่อได้รับชำระราคาค่าบริการ ระบบรองรับวงจรนี้อัตโนมัติทั้งฝั่งขายและฝั่งซื้อ:

### 3.1 ฝั่งให้บริการเงินเชื่อ (Deferred Output VAT)
1. **วันแจ้งหนี้บริการ (`trans_flag = 44` หรือ `250`, `inquiry_type = 2`, ยังไม่ออกใบกำกับภาษี)**:
   - บันทึกแถวใน `gl_journal_vat_sale` โดยตั้ง **`vat_type = 1`** (ยังไม่เข้า ภ.พ.30 งวดนี้)
   - โพสต์บัญชีพักภาษีขาย: `Dr 1121-00 ลูกหนี้การค้า / Cr 4130-00 รายได้ค่าบริการ + Cr 2125-00 ภาษีขายยังไม่ถึงกำหนด`
2. **วันรับชำระเงินและออกใบกำกับภาษี (`trans_flag = 239` ใบเสร็จรับเงิน)**:
   - สร้างแถวใหม่ใน `gl_journal_vat_sale` ของเอกสาร `239` โดยตั้ง **`vat_type = 0`** (เข้า ภ.พ.30 งวดที่รับเงิน!) และชี้ **`ref_doc_no = เลขที่บิลบริการเดิม`** พร้อมระบุเลขที่ใบกำกับภาษี `vat_doc_no`
   - โพสต์ล้างบัญชีพักเข้าภาษีขายจริง (`service.go:2424-2445`): `Dr 2125-00 ภาษีขายยังไม่ถึงกำหนด / Cr 2121-00 ภาษีขาย`

### 3.2 ฝั่งรับบริการเงินเชื่อ (Deferred Input VAT)
1. **วันรับใบแจ้งหนี้ค่าบริการ (`trans_flag = 12, 260` `inquiry_type = 2` หรือใบทะยอยรับ `310`)**:
   - บันทึกแถวใน `gl_journal_vat_buy` โดยตั้ง **`vat_type = 2`** (ยังไม่เคลมใน ภ.พ.30)
   - โพสต์บัญชีพักภาษีซื้อ: `Dr ค่าใช้จ่าย/ซื้อ + Dr 1152-00 ภาษีซื้อยังไม่ถึงกำหนด / Cr 2111-00 เจ้าหนี้การค้า`
2. **วันจ่ายชำระหนี้และได้รับใบกำกับภาษีซื้อ (`trans_flag = 19` หรือตั้งหนี้ `315`)**:
   - สร้างแถวใหม่ใน `gl_journal_vat_buy` โดยตั้ง **`vat_type = 0`** และชี้ **`ref_doc_no = เลขที่บิลเดิม`**
   - โพสต์ล้างบัญชีพักเข้าภาษีซื้อขอคืนได้ (`service.go:2453-2474`): `Dr 1151-00 ภาษีซื้อ / Cr 1152-00 ภาษีซื้อยังไม่ถึงกำหนด`

## 4. ภาษีหัก ณ ที่จ่าย (`gl_wht_list` + `gl_wht_list_detail` + `gl_wht_out_tracking`)

ข้อมูลภาษีหัก ณ ที่จ่ายถูกแบ่งเก็บใน 2 ตารางหลัก และ 1 ตารางติดตามหนังสือรับรอง:

| ตาราง | บทบาทและคอลัมน์สำคัญ |
|---|---|
| **`gl_wht_list`** | หัวรายการหัก ณ ที่จ่ายต่อใบรับรอง: `doc_no`, `trans_flag`, `doc_date`, `due_date` (วันที่หักภาษี), `cust_code` (รหัสผู้ถูกหัก/ผู้หัก), `tax_doc_no` (เลขที่หนังสือรับรอง), `tax_type` (`0` หรือประเภทแบบ ภ.ง.ด.3 บุคคลธรรมดา vs ภ.ง.ด.53 นิติบุคคล), `base_Result` / `tax_value` (ยอดรวมภาษีหัก ณ ที่จ่าย) |
| **`gl_wht_list_detail`** | รายละเอียดประเภทเงินได้แต่ละบรรทัด (มาตรา 40(2), 40(4), 3 เตรส ฯลฯ): `doc_no`, `trans_flag`, `line_number`, `description` (ประเภทเงินได้ เช่น ค่าบริการ ค่าเช่า ค่าขนส่ง), `amount` (ฐานเงินได้), `tax_rate` (อัตรา `%` เช่น `1, 2, 3, 5`), `tax_amount` (ภาษีที่หัก), `due_date` |
| **`gl_wht_out_tracking`** | ตารางติดตามสถานะการขอรับใบรับรอง 50 ทวิ จากลูกค้า (ฝั่ง AR ถูกหัก ณ ที่จ่าย `1153-00`, `rd_tax_export_wht.go:97-120`): เก็บสถานะ `PENDING`, `RECEIVED`, `WAIVED` เลขที่ใบรับรอง และวันที่ได้รับจริง |

### กฎสำคัญในการ Query ข้อมูลภาษีหัก ณ ที่จ่าย (`rd_tax_export_wht.go:257-450`)
1. **ใช้วันที่หักภาษีด้วย `COALESCE(d.due_date, h.due_date, h.doc_date)`**: เนื่องจากโค้ดยุค C# บางหน้าจอบันทึกวันที่หักภาษีไว้ที่ระดับบรรทัด `gl_wht_list_detail.due_date`
2. **แยกฝั่งเราหักคู่ค้า (ภ.ง.ด.3 / ภ.ง.ด.53 — บัญชี `2122-01`, `2122-02`) กับฝั่งลูกค้าหักเรา (50 ทวิ — บัญชี `1153-00`)**:
   - **ฝั่งจ่าย (เราหักผู้ขาย — ยื่น ภ.ง.ด.3/53)**: `trans_flag IN (10, 11, 12, 14, 16, 19, 25, 260, 262, 264, 315, 316, 317)` (และ `0/601` ฝั่งเจ้าหนี้) โดยใบลดหนี้ฝั่งจ่าย `trans_flag IN (16, 25, 262, 317)` มีตัวคูณเครื่องหมายเป็น `-1`
   - **ฝั่งรับ (ลูกค้าหักเรา — ติดตาม 50 ทวิ)**: `trans_flag IN (40, 44, 46, 48, 110, 239, 250, 252, 254, 1802)`
3. **กรองเอกสารต้นทางไม่ถูกยกเลิกเสมอ (`rdActiveWhtDocSQL`)**: ต้องตรวจว่าทั้ง `ic_trans`, `ap_ar_trans` และ `as_trans` ที่มี `(doc_no, trans_flag)` ตรงกัน ไม่มี `COALESCE(last_status, 0) <> 0`
