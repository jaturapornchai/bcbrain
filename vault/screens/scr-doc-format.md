# กำหนดรูปแบบเลขที่เอกสาร (เมนู 1012)

จอที่ผู้ใช้ตั้ง "ชนิดเอกสาร" แต่ละแบบ: รหัสรูปแบบ, รหัสหน้าจอที่ใช้, แพตเทิร์นเลขที่รัน, แบบฟอร์มพิมพ์, สมุดรายวัน GL, **กฎลงบัญชีอัตโนมัติ** และ **การส่ง e-Tax INET** รวมในจอเดียว (ตาราง `erp_doc_format` + ลูก 2 ตาราง `erp_doc_format_gl`, `erp_doc_format_etax`) เอกสารเก็บรหัสรูปแบบไว้ในคอลัมน์ `doc_format_code` (โค้ดอ่านจริงจาก `ic_trans`, `ap_ar_trans`, `cb_trans` ที่ `doc_picture.go:165-169`) ตารางและวิธีรันเลขดู [[tbl-erp-doc-format]], [[tbl-erp-doc-format-gl]] และ [[proc-doc-flow-numbering]]; ตัวลงบัญชีที่อ่านกฎ GL ไปใช้ดู [[acc-gl-template-engine]]

## วิธีเปิด และสิทธิ์
- เมนู 1012 "กำหนดรูปแบบเลขที่เอกสาร" (`menu_setup_doc_format`) อยู่ใต้ เริ่มต้น > ตั้งค่าองค์กร พนักงาน และเอกสาร (`bcMenu.json:179-180`) ลงทะเบียนจอที่ `screenRegistry.tsx:291-296` ตัวจัดกลุ่มเมนูนับเป็นเมนูข้อมูลหลัก (`MenuBar.tsx:84`) กลไกเมนูดู [[fe-screen-registry-menu]]
- **เฉพาะผู้ดูแลระบบ (Admin)**: เมนูนี้อยู่ใน `ADMIN_ONLY_MENU_SET` (`bcMenu.ts:325`, ข้อมูลเมนู `bcMenu.json:190`) ผู้ใช้ทั่วไปกดเปิดแล้วระบบขึ้นข้อความ "จำกัดสิทธิ์เฉพาะผู้ดูแลระบบ (Admin) เท่านั้น" (`TabWorkspace.tsx:542-548`) และถ้ามีแท็บนี้ค้างอยู่จะถูกปิด (`:519-534`) สิทธิ์เพิ่ม/แก้/ลบของจอนี้สำหรับผู้ใช้ทั่วไปจึงเป็นอ่านอย่างเดียวเสมอ (`:630`) ส่วนสิทธิ์รายจออื่นดู [[proc-permission-rights]]
- จอที่ให้เลือก "รูปแบบเอกสาร" ตอนเพิ่มใหม่อ่านรายการจากตารางนี้ เช่นจอต้นทุนแฝงเลือกรูปแบบประเภท `AFC` (`HiddenCostScreen.tsx:127`, ดู [[scr-hidden-cost]]) และจอสินค้าคงเหลือยกมาดึงรูปแบบเริ่มต้นประเภท `IB` (`StockBeginningBalanceScreen.tsx:956`) ส่วนช่องรหัสของจอลูกหนี้/เจ้าหนี้ ถ้าพิมพ์รหัสตรงกับ `erp_doc_format.code` backend จะรันรหัสถัดไปตามรูปแบบนั้น ถ้าไม่ตรงถือเป็นต้นรหัส (`master_autorun.go:81-122`)

## โครงจอ
- ซ้าย: รายการรูปแบบ (`BcDataList`) คอลัมน์ รหัสรูปแบบ, รหัสจอ, ชื่อรูปแบบเอกสาร, รูปแบบ (`:959-964`) ดึงจาก `erp_doc_format` เรียงรหัส สูงสุด 500 แถว (`:270-303`) ค้นจากรหัส/รหัสหน้าจอ/ชื่อ 1/ชื่อ 2/รูปแบบ เลือกแถวแรกให้เองตอนเปิดจอครั้งแรก (`:290-293`) ปุ่มคัดลอกอยู่ในแถบเครื่องมือรายการ (`onCopy={startCopy}`, `:953`) กลไกรายการดู [[scr-data-list-and-lookup]]
- ขวา: แถบหัว "หน้าจอบันทึก/แก้ไขข้อมูล" แสดง "บันทึกล่าสุด HH:MM:SS", "แก้ไขแล้ว N ช่อง" (`dirtyCount`) และป้าย "เพิ่มรายการใหม่" / "โหมดแก้ไข" (`:970-986`) แถบปุ่ม + รหัสเมนู + ชื่อจอ (`:989-1069`) การ์ด "รายละเอียดรูปแบบเอกสาร (Header Properties)" แถบ "ข้ามไปยังส่วน" แล้วตามด้วยส่วน GL, Help, e-Tax เรียงลงมาในหน้าเดียว (ไม่ใช่แท็บสลับ)
- ปุ่มโหมดดู: **แก้ไข**, **เพิ่มใหม่**, **ลบ**, **ปิดหน้าจอ** (ปุ่มปิดหน้าจอโผล่เมื่อจอเปิดจากหน้าต่างที่ส่ง `onClose` มาให้); โหมดแก้: **บันทึก**, **ปิดหน้าจอ** (= ยกเลิกการแก้) ปุ่มถูกปิดตามสิทธิ์ (`:991-1059`)
- คีย์ลัด **Ctrl+S** บันทึก (เมื่ออยู่โหมดแก้ ไม่กำลังบันทึก และมีสิทธิ์), **Esc** ยกเลิกการแก้ไข ทำงานเฉพาะเมื่อจอนี้มองเห็นอยู่ (`:886-899`; คอมเมนต์ในโค้ดเขียน "F12 / Esc" แต่ F12 ไม่ได้ผูก)
- ยังไม่เลือกรายการและไม่ได้เพิ่มใหม่ ฝั่งขวาแสดง "เลือกรายการทางซ้ายมือ หรือคลิกปุ่ม "เพิ่มใหม่" เพื่อเริ่มสร้างรูปแบบเลขที่เอกสาร" (`:2122-2126`)

## การเพิ่ม แก้ คัดลอก ยกเลิก
- **เพิ่มใหม่** (`startNew`, `:412-448`): ล้างทุกช่อง ตั้งค่าเริ่มต้น รหัสหน้าจอ `IB`, รูปแบบ `@YYMM####`, การรันเลข "ต่อเนื่อง", ประเภทภาษี 0, ไม่ติ๊กส่ง e-Tax, ตาราง GL ว่าง
- **แก้ไข** (`startEdit`, `:451-456`) เปิดช่องให้พิมพ์ (ดับเบิลคลิกแถวหรือปุ่มดินสอในรายการก็เข้าโหมดแก้ได้ โดยไม่ตรวจสิทธิ์ก่อน แล้วไปถูกสกัดตอนบันทึก `:941-952`)
- **คัดลอก** (`startCopy`, `:508-518`): ต้องเลือกรายการและมีสิทธิ์เพิ่ม เปิดฟอร์มเพิ่มใหม่ โดยรหัสต่อท้าย `_COPY` และชื่อไทยต่อท้าย " (สำเนา)" ช่องอื่นรวมทั้งแถว GL และค่า e-Tax ที่แสดงอยู่ไม่ถูกล้าง ต้องตรวจก่อนบันทึก
- เปลี่ยนรายการ/กดเพิ่มใหม่ขณะมีการแก้ค้าง: ระบบถาม "ยังไม่ได้บันทึกข้อมูล" / "คุณมีการแก้ไขข้อมูลค้างอยู่ ต้องการเปลี่ยนรายการโดยไม่บันทึกหรือไม่?" ปุ่ม "ละทิ้งการแก้ไข" หรือ "แก้ไขต่อ" (`:459-476`, `:917-932`)
- **ปิดหน้าจอ/Esc** ขณะแก้ (`cancelEdit`, `:479-505`): ถ้ามีการแก้ไขถาม "เตือน" / "มีการแก้ไขข้อมูลบางส่วน" ขึ้นบรรทัดใหม่ "ต้องการยกเลิกการแก้ไขหรือไม่" ปุ่ม "ตกลง"/"ยกเลิก" แล้วโหลดข้อมูลรายการที่เลือกกลับมาใหม่

## ช่องหัวเอกสาร (`:1107-1609`)
| ช่อง | ข้อกำหนด |
|---|---|
| รหัสรูปแบบเอกสาร | **บังคับ** ตัวพิมพ์ใหญ่อัตโนมัติ แก้ได้เฉพาะตอนเพิ่มใหม่/คัดลอก (ช่องถูกปิดเมื่อเปิดรายการที่มีอยู่แล้ว, `:1121`) ตรวจรหัสซ้ำก่อนบันทึก |
| รหัสหน้าจอ (Screen Code) | **บังคับ** พิมพ์เองหรือเลือกจากรายการ 35 รหัสมาตรฐาน (`STANDARD_SCREEN_CODES`, `:94-130`) IB, IC, IF, IO, IR, IM, CO, IA, IS (สต๊อก/ข้อมูลหลัก), PR, PO, PU, PT, PA (ซื้อ), SO, SR, SS, SI, ST, SA, SIP (ขาย), JV (บัญชี), DA, DB, DC (เจ้าหนี้ยกมา), EA, EB, EC (ลูกหนี้ยกมา), OI, EPO, DM, WM, TM, CHB, CPB (เงินสด/ธนาคาร) พิมพ์รหัสอื่นนอกรายการก็ได้ (ใช้ `datalist` ไม่ได้บังคับ, `:1147`, `:1161-1167`) |
| ชื่อรูปแบบเอกสาร (ไทย) | **บังคับ** |
| ชื่อรูปแบบเอกสาร (อังกฤษ) | ไม่บังคับ |
| รูปแบบเอกสาร (Format) | ค่าเริ่มต้น `@YYMM####` ถ้าปล่อยว่างตอนบันทึกระบบใส่ `@YYMM####` ให้ |
| รูปแบบใบกำกับภาษี (Tax Format) | ไม่บังคับ |
| การรันเลขที่เอกสาร (Doc Running) | ต่อเนื่อง (ค่าเริ่มต้น) / รายปี / รายเดือน / รายวัน (`:144-149`) |
| รหัสแบบพิมพ์หลัก (Form Code) | พิมพ์เองหรือเลือกจากรายชื่อแบบพิมพ์สำเร็จรูป (`READY_DOC_FORM_TEMPLATES` ของ `GlobalDocFormPrintModal`, `:37`, `:1154-1160`) เฉพาะช่องนี้ช่องเดียวที่ผูกรายชื่อนี้ (`:1293`) |
| รหัสแบบพิมพ์ 1-5 | ข้อความอิสระ ไม่มีรายการให้เลือก (`:1308-1414`) |
| สมุดรายวัน (GL Journal Book) | ช่องรหัส + ปุ่มค้นหา `gl_journal_book` ชื่อสมุดแสดงต่อท้ายในวงเล็บ — **เห็นเฉพาะรุ่นที่มี GL** (`:1416-1464`) |
| โฟลเดอร์สำหรับจัดเก็บไฟล์ Scan / Computer ID สำหรับ Scan | ข้อความ ไม่บังคับ (`:1467-1512`) |
| คำอธิบายรายวัน GL | ข้อความที่ลงสมุดรายวันอัตโนมัติ — เฉพาะรุ่นที่มี GL (`:1517-1538`) |
| กำหนดสาขาที่ใช้งาน + รายชื่อสาขาที่อนุญาต | ติ๊กแล้วจึงพิมพ์รหัสสาขาคั่นด้วยจุลภาค — **เห็นเฉพาะรุ่นที่มีแผนก/สาขา** (`:1540-1579`) |
| ประเภทภาษี (VAT Type) | 0 ภาษีปกติ / 1 แยกนอก / 2 รวมใน / 3 อัตราศูนย์ (`:151-156`) |

รุ่น Starter ปิด `hasGl` และ `hasDepartmentAndBranch` (`editionConfig.ts:47-63`) ช่องสมุดรายวัน คำอธิบาย GL สาขา ปุ่มข้ามไปส่วน GL และตาราง GL จึงไม่โผล่ (แถบหัว "ส่วนที่ 2 GL" ยังแสดงและปุ่ม Get Format ยังโผล่ตอนแก้ ส่วนตารางถูกซ่อน, `:1643-1674`) รุ่น Account และ Pro เปิดครบ (`:65-82`, `:83-99`)

## ตัวอย่างเลขที่ (Preview)
- ในการ์ดหัวมีป้าย "ตัวอย่างผลลัพธ์" (`:1094-1097`) จาก `generateFormatPreview` (`:159-183`): แทน `YYYY/YY/MM/DD` ด้วยวันที่ของเครื่อง (ปี ค.ศ. จาก `getFullYear`) แทน `@` ด้วยรหัสรูปแบบ แล้วนับ `#` ชุดแรกเป็นเลขรันขึ้นต้นที่ `0001` ถ้าช่อง Format ว่างแสดงรหัสรูปแบบ (หรือ `---`) เป็นเพียงตัวอย่างฝั่งหน้าจอ เลขจริงขอจากฝั่ง backend ตามตาราง `erp_doc_format` และเลขล่าสุดในตารางธุรกรรม (`frontend/src/lib/doc-no.ts:13`, `query-client.ts:807`)
- ส่วน Help มีช่องทดลองพิมพ์รูปแบบแล้วดูผล (`:1915`) ใช้ฟังก์ชันเดียวกัน

## ส่วน GL (ผูกบัญชีรายวันอัตโนมัติ, `:1643-1883`)
ตารางกฎลงบัญชีของรูปแบบนี้ (ตาราง `erp_doc_format_gl`) คอลัมน์: ลำดับ (#), เลขเงื่อนไข, ชื่อเงื่อนไข, กรณี/สูตร, ผังบัญชี (เดบิต), ผังบัญชี (เครดิต), ชื่อบัญชี (อ่านอย่างเดียว แสดงชื่อที่ได้จากการค้นหา), คำอธิบาย (พิมพ์ได้)
- ตอนแก้: ที่จับกดค้างแล้วลากเพื่อย้ายแถว (`RowMoveButtons`, เลขลำดับเรียงใหม่), ปุ่ม **เพิ่มแถว**, และ **ลบแถว** (โผล่เมื่อคลิกเลือกแถวแล้ว) แถวใหม่เลขเงื่อนไขเป็น 0 (`:791-824`, `:1706-1720`, `:1851-1879`)
- ปุ่มค้นหาผังบัญชีในแถว เปิดหน้าต่างค้นหา `gl_chart_of_account` เลือกด้านเดบิตจะ **ล้างด้านเครดิตของแถวนั้น** และเลือกด้านเครดิตจะล้างด้านเดบิต พร้อมใส่ชื่อบัญชีในคอลัมน์ "ชื่อบัญชี" (`:2154-2167`) แต่ถ้าพิมพ์รหัสเองในช่องเดบิตและเครดิตพร้อมกันหน้าจอไม่ห้าม
- `condition_number` คือรหัสการกระทำที่ตัวลงบัญชีฝั่ง backend ใช้เลือกกฎ ไม่ใช่เลขแถว (คอมเมนต์ในโค้ด `:371`) ดังนั้นแถวที่เพิ่มเองจะมีเลข 0 จนกว่าจะแก้
- **Get Format** (`:850-878`, ปุ่มโผล่เฉพาะตอนแก้): ต้องกรอกรหัสหน้าจอก่อน (ไม่งั้นขึ้น "กรุณาเลือกรหัสหน้าจอก่อนดึงรูปแบบ") แล้วเรียก `POST /api/process/gl/template-defaults` (`gl_template_handler.go:13`, สิทธิ์ระดับอ่าน `permission.go:25`) ขอแม่แบบมาตรฐานของรหัสหน้าจอนั้น ถาม "ต้องการล้างของเก่าหรือไม่" — **ล้างของเก่า** ใช้บัญชีของแม่แบบ, **ไม่ล้าง** จะเก็บบัญชีเดบิต/เครดิต/ชื่อบัญชีของแถวที่รหัสตรงกัน (`code_compare`) ถ้าไม่มีแถวตรงกันบัญชีเป็นว่าง ทั้งสองทางตารางเดิมทั้งชุดถูกแทนด้วยแถวของแม่แบบ แถวที่แก้เองหรือเพิ่มเองซึ่งไม่ตรงกับแม่แบบจะหายไป (`applyGlFormatPreset`, `:827-847`)
- โหลดตาราง GL มาจาก `erp_doc_format_gl` เรียงตาม `line_number` (`:358-383`)

## ส่วน Help (`:1886-2009`)
หัวส่วนเขียน "ส่วนที่ 3" ทั้งที่แถบ "ข้ามไปยังส่วน" เรียกว่า "ส่วนที่ 4" (และ e-Tax เป็นกลับกัน, `:1616-1621`, `:1889`, `:2014`) เนื้อหา: กล่องทดลองพิมพ์รูปแบบแล้วดูตัวอย่าง ตารางสัญลักษณ์ `@`, `@YY`, `@YYYY`, `@MM`, `@DD`, `####` พร้อมความหมายและตัวอย่าง และตารางรหัสหน้าจอมาตรฐานเป็นการ์ด ตอนแก้ คลิกการ์ดจะใส่รหัสนั้นลงช่อง Screen Code (`:1985-1990`)

## ส่วน e-Tax INET (`:2011-2120`)
ติ๊ก "ส่งเอกสารไปยังระบบ e-Tax Invoice / Receipt ผ่าน INET" ช่องที่เหลือเปิดเมื่อติ๊กแล้วและอยู่โหมดแก้: ประเภทเอกสาร e-Tax เลือกจาก `-- ไม่ระบุ --`, T03, T04, 388, 80, 81, 380, T01, T02 (`ETAX_DOCUMENT_TYPES`, `:132-142`) พอเลือกประเภทใดระบบเติมชื่อประเภทเอกสาร e-Tax ให้ด้วยข้อความหลังเครื่องหมาย " - " ของป้าย (แก้ทับได้, `:2045-2053`) และ รหัสฟอร์มพิมพ์ e-Tax เก็บ 1 แถวต่อรูปแบบเอกสารที่ `erp_doc_format_etax` (เก็บทั้งลำดับประเภทและรหัสประเภท, `:645-659`) ค่าตั้งระดับบริษัทของ e-Tax อยู่ที่หมวด `etax` ของ [[scr-options]]

## บันทึกและลบ
- **บันทึก** (`handleSave`, `:521-719`): ตรวจสิทธิ์ ("ไม่มีสิทธิ์บันทึกข้อมูล") → รหัส ("กรุณาระบุรหัสรูปแบบเอกสาร (Code)") → ชื่อไทย ("กรุณาระบุชื่อรูปแบบเอกสาร") → รหัสหน้าจอ ("กรุณาระบุรหัสหน้าจอ (Screen Code)") → ตอนเพิ่มใหม่ตรวจรหัสซ้ำ (ไม่สนตัวพิมพ์ ขึ้น `รหัส "X" มีอยู่ในระบบแล้ว กรุณาระบุรหัสใหม่`) แล้วรวมคำสั่งเป็นชุดเดียว (`queryExecBatch`, ทำพร้อมกันหรือล้มพร้อมกัน) ตามลำดับ: INSERT หรือ UPDATE หัว → (แก้รายการเดิม) ลบ `erp_doc_format_gl` ทั้งหมด → ลบแล้วเพิ่ม `erp_doc_format_etax` 1 แถวทุกครั้ง แม้ไม่ติ๊กส่ง → เพิ่มแถว GL ปัจจุบันใหม่ (เลขแถว 1..n) สำเร็จขึ้น `บันทึกรูปแบบเอกสาร "X" เรียบร้อยแล้ว` แล้วออกจากโหมดแก้และโหลดรายการใหม่ รหัสและรหัสหน้าจอถูกแปลงเป็นตัวพิมพ์ใหญ่ก่อนเก็บ
- **ลบ** (`handleDelete`, `:722-787`): ปุ่ม "ลบ" ในโหมดดู ลบทีละรายการที่เลือก (ฟังก์ชันรองรับหลายรหัสแต่หน้าจอส่งทีละรหัส) ถามยืนยัน "ยืนยันการลบ" / "คุณต้องการลบรูปแบบเอกสารที่เลือกจำนวน N รายการ ใช่หรือไม่?" แล้วตรวจว่ารหัสถูกใช้ใน [[tbl-ic-trans]] (`doc_format_code`) หรือสมุดรายวัน `gl_journal` หรือไม่ ถ้ามีขึ้น "ห้ามลบ" / `รหัสรูปแบบเอกสาร [X] ถูกใช้งานใน<เอกสารซื้อ-ขาย-คลัง หรือ สมุดรายวัน>แล้ว ไม่สามารถลบได้` ผ่านแล้วลบ etax + GL + หัว ในชุดเดียว สำเร็จขึ้น "ลบสำเร็จ"

## ข้อควรระวัง
- ตรวจอ้างอิงตอนลบดูแค่ `ic_trans` กับ `gl_journal` (`:735-738`) แต่ `ap_ar_trans` และ `cb_trans` ก็มีคอลัมน์ `doc_format_code` ที่เอกสารจริงใช้ (`doc_picture.go:165-169`) จอนี้ไม่ได้ตรวจ จึงลบรูปแบบที่ลูกหนี้-เจ้าหนี้หรือเงินสด-ธนาคารใช้อยู่ได้ ตารางอื่นที่ใช้ตัวรันเลขร่วมกัน (`as_trans`, `ic_hidden_cost_process` ตาม [[tbl-erp-doc-format]]) ยังไม่ได้ตรวจในโค้ดจอนี้
- ช่อง "รหัสหน้าจอ" แก้ได้ตอนแก้รายการที่มีอยู่แล้ว และ UPDATE เปลี่ยน `screen_code` โดยไม่ตรวจว่ามีเอกสารใช้รูปแบบนี้แล้วหรือไม่ (`:619`)
- แก้กฎ GL แล้วบันทึก เป็นการลบ-สร้างใหม่ทั้งชุด แถวที่ลบตอนแก้จึงหายจริง (ไม่มีประวัติ, `:640`, `:676-681`)
- Get Format แทนที่ตารางทั้งชุดทั้งสองทาง (ดูส่วน GL) กดแล้วยังไม่มีผลถึงฐานข้อมูลจนกว่าจะกดบันทึก
- ตารางสัญลักษณ์ใน Help แสดงเป็น `@YY`, `@MM` ฯลฯ ซึ่ง `@` ในแพตเทิร์นแทนรหัสรูปแบบ ส่วน `YY/MM` เป็นปี-เดือน ดังนั้นต้องเขียนเช่น `@YYMM####` (รหัส+ปี+เดือน+เลขรัน) ไม่ใช่ต้องพิมพ์ `@` ก่อนทุกตัว
- การบันทึก/ลบ ประกอบข้อความ SQL ในเบราว์เซอร์ (`escapeSql` แล้วส่ง `queryExecBatch`, `:566-761`) การตรวจสิทธิ์ที่เห็นในจอนี้เป็นฝั่งหน้าจอ (`rights`)
