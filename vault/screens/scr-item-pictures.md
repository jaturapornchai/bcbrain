# กำหนดรูปภาพและไฟล์แนบ (สินค้า / บาร์โค้ด / พนักงาน / สินทรัพย์ / เอกสาร)

สองจอหน้าตาเหมือนกัน (รายการซ้าย / ข้อมูลอ้างอิงอ่านอย่างเดียวและกล่องไฟล์ขวา) ใช้แนบรูปและไฟล์เอกสารให้ "ข้อมูลหลัก" หรือ "เอกสาร" ผ่านกล่องกลาง `PictureGallery` ร่วมกัน ฝั่ง Go เป็นผู้ตรวจชนิดไฟล์ ขนาด คีย์ และเก็บไฟล์ (`/api/process/itempicture/*` และ `/api/process/docpicture/*`) ดู [[proc-doc-item-pictures]]

## ItemPictureScreen
- **รายการซ้าย** ค้นจากเซิร์ฟเวอร์ `POST /api/process/itempicture/list` ด้วย `{kind, keyword, page}` ครั้งละ 50 แถว (`item_picture.go:24`) ค้นหลายคำเป็น AND สูงสุด 8 คำ (`:66-72`) คอลัมน์ รหัส (ป้ายตามชนิด: รหัสสินค้า / รหัสพนักงาน / รหัสสินทรัพย์; โหมดบาร์โค้ดเป็น "บาร์โค้ด" + "รหัสสินค้า"), ชื่อ, หน่วย (พนักงานเป็น "แผนก"), "รูป" (จำนวนไฟล์) (`ItemPictureScreen.tsx:140-146`) ท้ายรายการมี "ทั้งหมด N รายการ", ปุ่ม ก่อนหน้า / ถัดไป, "หน้า x/y" (`:187-194`) โหลดรายการแล้วเลือกแถวแรกให้เอง (`:89`)
- **แหล่งข้อมูลรายการ** สินค้า = `ic_inventory` (หน่วย `unit_standard`), บาร์โค้ด = `ic_inventory_barcode` เชื่อมสินค้า (ชื่อใช้ `description` ถ้ามี ไม่งั้นชื่อสินค้า), พนักงาน = `erp_user` (ช่องหน่วยใช้ `title` ถ้ามี ไม่งั้น `branch_code`), สินทรัพย์ = `as_asset` (`item_picture.go:105-140`)
- **ขวา** ช่องข้อมูลอ้างอิงอ่านอย่างเดียว (รหัส / ชื่อ / หน่วยนับ หรือ แผนก; โหมดบาร์โค้ดเพิ่ม "บาร์โค้ด" นำหน้า) แล้วกล่องไฟล์ ป้ายกล่อง "รูปภาพสินค้า" / "รูปภาพบาร์โค้ด" / "รูปภาพพนักงาน" / "รูปภาพสินทรัพย์" (`:55-59,147-149,246-254`) จำนวนสูงสุดมาจากเซิร์ฟเวอร์ (`view.max`, `:77`) ซึ่งตอนนี้ส่ง 0 = ไม่จำกัด (`item_picture.go:23,206`) ข้อความช่วยเมื่อยังไม่มีไฟล์ "ยังไม่มีรูปภาพ" (แก้ไม่ได้: "ยังไม่มีรูปภาพ (สินค้านี้ยังไม่พร้อมแก้ไข)"), ขณะแก้ "กดปุ่ม เลือกรูป เพื่อแนบรูปภาพ", ยังไม่เลือกรายการ "เลือกรายการจากรายการด้านซ้าย" (`:251,257`)
- **ปุ่ม** โหมดดู = **แก้ไข** (ปิดเมื่อไม่มีสิทธิ์แก้), **ลบ** (ปิดเมื่อรายการแก้ไม่ได้ ไม่มีไฟล์ หรือไม่มีสิทธิ์ลบ; ถามยืนยัน `ลบรูปภาพทั้งหมดของ <คีย์> ?` แล้วส่งบันทึกรายการว่าง), **ปิดหน้าจอ** (แสดงเมื่อมีฟังก์ชัน `onClose` ส่งเข้ามา) โหมดแก้ = **บันทึก** (กดได้เมื่อมีการเปลี่ยน) และ **ปิดหน้าจอ** ซึ่งทำหน้าที่ยกเลิกการแก้ (`:209-234,262-269`) แถบสถานะแสดง "บันทึกล่าสุด HH:MM:SS", "แก้ไขแล้ว", "โหมดแก้ไข" (`:202-208`)
- **คีย์ลัด** Ctrl+S บันทึก, Esc ยกเลิก ทำงานเฉพาะตอนอยู่โหมดแก้และแท็บนั้นมองเห็นอยู่ (`ScreenFrame.tsx:37-57`; คอมเมนต์ในไฟล์พูดถึง F12 แต่โค้ดผูกแค่ Ctrl+S) ดับเบิลคลิกแถว = เลือกแล้วเข้าโหมดแก้ทันทีถ้ารายการนั้นแก้ได้ (`:179`) ทางนี้ไม่ตรวจสิทธิ์แก้ไข ไปถูกบล็อกตอนบันทึกแทน (`:121-123`)
- **กฎแก้ไขได้ไหม** สินค้าและบาร์โค้ดแก้ได้เมื่อ `ic_inventory.update_detail = 1`; พนักงานและสินทรัพย์แก้ได้เสมอ (`item_picture.go:110,134,118,126`) กดแก้ไขรายการที่แก้ไม่ได้ขึ้น "สินค้านี้ยังไม่พร้อมแก้ไข  จึงแนบรูปไม่ได้" (มีช่องว่างสองตัว `:112-114`) และ Go ตอบข้อความเดียวกันซ้ำตอนบันทึก (`item_picture.go:270-272`)
- **สิทธิ์** บันทึกที่มีไฟล์ใช้สิทธิ์ "แก้ไข" ส่วนบันทึกรายการว่าง (ปุ่มลบ) ใช้สิทธิ์ "ลบ" ไม่มีสิทธิ์ขึ้น `คุณไม่มีสิทธิ์ "แก้ไขข้อมูล"` หรือ `"ลบข้อมูล"` ในหน้าจอนี้ กรุณาติดต่อผู้ดูแลระบบ (Admin) (`ItemPictureScreen.tsx:118-123`) ฝั่ง Go จัด `itempicture/save` เป็นงานเขียน ส่วน list / get / image เป็นงานอ่าน (`permission.go:31,42`)
- **เปลี่ยนรายการ** ขณะแก้และมีไฟล์ค้าง ขึ้น "มีรูปที่ยังไม่บันทึก กรุณาบันทึกหรือยกเลิกก่อนเปลี่ยนรายการ" (`:103`)
- **บันทึก** ส่ง `POST /api/process/itempicture/save` เป็นรายการตามลำดับบนจอ: ไฟล์เดิม `{id}`, ไฟล์ใหม่ `{data, name, mime}` สำเร็จขึ้น "บันทึกรูปภาพแล้ว" หรือ "ลบรูปภาพแล้ว" และปรับตัวเลขในคอลัมน์ "รูป" ของแถวนั้น (`:125-134`)

## DocumentPictureScreen
- **หัวรายการ** (ยกเว้นสมุดรายวัน) ช่องเลือก **ประเภทเอกสาร** ดึงจาก `POST /api/process/docpicture/formats` แสดงเป็น "รหัส - ชื่อ" เลือกตัวแรกให้เอง ต้องเลือกประเภทก่อนจึงโหลดรายการ (`DocumentPictureScreen.tsx:81-109,186-194`) ประเภทที่ให้เลือกคือแถวใน `erp_doc_format` ที่ `screen_code` อยู่ในชุดของแต่ละหมวด (`doc_picture.go:46-54,91-95`) เปลี่ยนประเภทขณะมีไฟล์ค้างขึ้น "มีรูปที่ยังไม่บันทึก กรุณาบันทึกหรือยกเลิกก่อน" (`:128-133`)
- **รายการเอกสาร** `POST /api/process/docpicture/docs` ครั้งละ 50 แถว เอกสารหมวดทั่วไปรวมจาก `ic_trans`, `ap_ar_trans`, `cb_trans` ที่ `doc_format_code` ตรงประเภท เรียงวันที่ใหม่ก่อน ส่วนสมุดรายวันอ่านจาก `gl_journal` (`doc_picture.go:135-194`) คอลัมน์ วันที่เอกสาร, เลขที่เอกสาร, เลขที่อ้างอิง, หมายเหตุ (สมุดรายวันเป็น วันที่เอกสาร, เลขที่เอกสาร, สมุดรายวัน, คำอธิบาย) ท้ายรายการ "ทั้งหมด N เอกสาร" (`DocumentPictureScreen.tsx:157-169,211-218`)
- **ข้อมูลอ้างอิงขวา** อ่านอย่างเดียว ทั่วไป: วันที่เอกสาร, เลขที่เอกสาร, วันที่เอกสารอ้างอิง, เลขที่เอกสารอ้างอิง, หมายเหตุ; สมุดรายวัน: วันที่เอกสาร, เลขที่เอกสาร, สมุดรายวัน, คำอธิบาย (`:171-173`) กล่องไฟล์ชื่อ "รูปภาพและไฟล์แนบเอกสาร" ไม่จำกัดจำนวน (`MAX_IMAGES = 0`, `:28,270-278`) ข้อความช่วย: ว่างและกำลังแก้ "กดปุ่ม เลือกรูป / ไฟล์แนบ เพื่อแนบรูปภาพหรือไฟล์เอกสาร (PDF, XLS, XLSX, CSV, DOC, ZIP)", ว่างและดูอย่างเดียว "เอกสารนี้ยังไม่มีรูปภาพหรือไฟล์แนบ"
- **คีย์เอกสาร** หน้าจอส่ง `{module, formatCode, docNo}` หรือสำหรับ GL `{module, docNo, docDate, bookCode}` (`:116-117`) Go ตรวจว่าเอกสารมีอยู่จริงก่อน แล้วเก็บไฟล์ใต้ `image_id` = เลขที่เอกสาร (GL: วันที่ `d/MM/yyyy` ต่อกับเลขที่เอกสารและรหัสสมุด ตัด "/" ออก ปีพุทธศักราชเมื่อ `erp_option.year_type = 1` หรือยังไม่มีแถวตั้งค่า) ยาวไม่เกิน 50 ตัวอักษร (`doc_picture.go:204-264`)
- **บันทึก** `POST /api/process/docpicture/save` สำเร็จขึ้น "บันทึกรูปภาพและไฟล์แนบเอกสารแล้ว" หรือ "ลบรูปภาพและไฟล์แนบของเอกสารแล้ว" ปุ่มลบถาม `ลบรูปภาพทั้งหมดของเอกสาร <เลขที่> ?` (`:135-152,289-295`) เปลี่ยนเอกสารขณะมีไฟล์ค้างขึ้น "มีรูปที่ยังไม่บันทึก กรุณาบันทึกหรือยกเลิกก่อนเปลี่ยนเอกสาร" (`:120`)
- **ปุ่ม / คีย์ลัด / สิทธิ์** เหมือน ItemPictureScreen ต่างตรงดับเบิลคลิกแถวเข้าโหมดแก้เสมอ ไม่ตรวจสิทธิ์และไม่มีเงื่อนไข "แก้ได้" (`:203`) การบันทึก Go ไม่เขียน `master_logs` (ต่างจากจอรูปสินค้า)

## กล่องไฟล์กลาง (`PictureGallery`)
- **ชนิดไฟล์** รูป PNG, JPG, WEBP, GIF, BMP และเอกสาร PDF, XLS, XLSX, CSV, DOC, DOCX, PPT, PPTX, TXT, ZIP ขนาดไม่เกิน **25 MB** ต่อไฟล์ (`PictureGallery.tsx:18-40`) ผิดชนิดหรือเกินขนาดขึ้น `<ชื่อไฟล์>: รองรับไฟล์รูปภาพ (PNG, JPG, WEBP, GIF, BMP) และไฟล์เอกสาร (PDF, XLS, XLSX, CSV, DOC, DOCX, PPT, PPTX, TXT, ZIP) ขนาดไม่เกิน 25 MB ต่อไฟล์` (`:179-185`) กรณีกำหนดจำนวนสูงสุดและแนบเกินขึ้น `แนบไฟล์ได้ไม่เกิน N รายการ` (`:176-178`) ซึ่งไม่เกิดขึ้นกับสองจอนี้เพราะส่งค่า 0 โค้ดฝั่งหน้าจอและ Go ยอมรับ `.json` ด้วย (`PictureGallery.tsx:37-38`, `doc_picture.go:477`) แต่ตัวเลือกไฟล์และข้อความไม่ได้ระบุ
- **ส่วนหัวกล่อง** `<ป้าย> (N ไฟล์)` (หรือ `(n/max)` เมื่อกำหนดจำนวนสูงสุด) ตามด้วยป้าย "MinIO Object Storage · ไม่จำกัดจำนวน" ขวามือมีปุ่ม **เลือกรูป / ไฟล์แนบ** เฉพาะโหมดแก้ กดแล้วเปิดตัวเลือกไฟล์พร้อมแผงลากวางไฟล์ (ปุ่ม "เลือกไฟล์จากเครื่อง..." และ "ปิด") (`:196-264`)
- **ภาพย่อ** กล่อง 80 px ต่อไฟล์: รูปแสดงภาพ ส่วน PDF / สเปรดชีต / ZIP / เอกสารแสดงไอคอน ป้ายนามสกุล และชื่อไฟล์ ปุ่ม X "ลบไฟล์นี้" มุมบนขวา (เฉพาะโหมดแก้) คลิกภาพย่อเพื่อดูรายละเอียดด้านล่าง (`:270-324`)
- **รายละเอียดไฟล์ที่เลือก** ป้ายชนิด ชื่อไฟล์ ขนาด ลิงก์ "ดาวน์โหลดไฟล์" และ "เปิดแท็บใหม่" (ไม่แสดงถ้าไฟล์ยังเป็น `data:` ที่ยังไม่บันทึก) รูปแสดงภาพขยาย, PDF แสดงในกรอบ iframe, ชนิดอื่นแสดงไอคอนกับปุ่ม "ดาวน์โหลด <ชื่อ>" (`:326-407`)
- **ที่มาของภาพย่อ** ไฟล์ที่เก็บแล้วใช้ `image_url` ถ้ามี (รูปจะต่อ `&variant=thumbnail` ให้ผ่าน `thumbUrl`, `frontend/src/lib/utils.ts:37-41`) ไม่งั้นดึงจาก `/api/process/itempicture/image?id=` หรือ `/api/process/docpicture/image?id=` (`ItemPictureScreen.tsx:28-48`, `DocumentPictureScreen.tsx:32-52`)

## ฝั่ง Go ตอนบันทึก
- ตรวจเนื้อไฟล์จริงไม่ใช่แค่นามสกุล: รับรูป 5 แบบ, PDF, OLE (xls/doc/ppt), ZIP/OOXML, csv/txt/json และปฏิเสธเนื้อที่เป็น HTML / script / SVG (`doc_picture.go:402-483`) ข้อความผิดพลาด "ไฟล์ที่ N ไม่รองรับ (...)", "ไฟล์ที่ N ใหญ่เกิน 25 MB", "ไฟล์ที่ N อ่านไม่ได้" (`:509-555`)
- บันทึกคือการแทนที่ทั้งชุดต่อคีย์: ล็อกด้วย advisory lock, ตรวจว่าไฟล์เดิมที่ขอเก็บยังอยู่ครบ (ไม่งั้น "ไฟล์แนบนี้ถูกเปลี่ยนโดยผู้ใช้อื่น กรุณาเปิดรายการใหม่แล้วทำอีกครั้ง"), ลบไฟล์ที่ไม่ได้เก็บ, เรียง `image_order` ใหม่จาก 0 ตามลำดับบนจอ (`:603-664`)
- ไฟล์ใหม่ขึ้น MinIO ใต้โฟลเดอร์ `<ฐานข้อมูล>/item_attachments` (สินค้า) หรือ `doc_attachments` (เอกสาร) แล้วเก็บเฉพาะลิงก์ `/api/crm/image?key=...&name=...&mime=...&size=...` ในคอลัมน์ `image_url`; ถ้าไม่มีที่เก็บไฟล์หรืออัปโหลดไม่สำเร็จจะเก็บไบต์ลงคอลัมน์ `image_file` แทน (`:623-657`) ตาราง: สินค้า/บาร์โค้ด/พนักงาน/สินทรัพย์ใช้ `images`, เอกสารใช้ `bc_doc_images` (`:34-37`)
- ลิงก์ในแถวต้องชี้เข้าโฟลเดอร์ของบริษัทเดียวกันจึงถูกส่งกลับ (`ownStorageURL`, `:313-324`)
- ขนาดคำขอรวมต่อครั้ง: จอเอกสารรับถึง 256 MB (`docpicture_handler.go:31-32`) แต่จอรูปสินค้ารับ 48 MB (`stocktools_handler.go:39-40`) ในขณะที่ไฟล์เดี่ยวใหญ่ได้ 25 MB (base64 ทำให้ใหญ่ขึ้นราว 1 ใน 3)
- จอรูปสินค้าบันทึกแล้วเขียนแถวใน `master_logs` (เมนู `ItemPicture` หรือ `ItemBarcodePicture`) (`item_picture.go:280-290`)

## ข้อควรระวัง
- จอสินค้า [[scr-item-master]] ส่วน 4 "รูปภาพสินค้า" อัปโหลดเข้า MinIO ผ่าน `/api/crm/upload` (`ItemScreen.tsx:1195,1297`) และเขียนตาราง `images` ตัวเดียวกับจอนี้ (`image_id` = รหัสสินค้า) แต่เขียนเฉพาะช่อง `image_order` 0-4 ที่ผู้ใช้เปลี่ยน (`item_master.go:780-793`) ขณะที่จอนี้แทนที่ทั้งชุดและเรียง `image_order` ใหม่ ทำให้ลำดับช่องในจอสินค้าเปลี่ยนไปได้หลังบันทึกจากจอนี้
- รูปของ "ข้อมูลสินค้าเพิ่มเติม" ในจอ [[scr-item-detail-2]] ดูได้อย่างเดียว: ปุ่ม "รูปภาพสินค้า (N)" (`ItemDetail2Screen.tsx:766`) ดึงจาก `itempicture/get` (`:373`) แล้วแสดงด้วยกล่องกลาง `editing={false}` (`:785-793`)
- ตัวกรองรายการเอกสารและชุดประเภทเอกสารถูกกำหนดที่ฝั่ง Go ไม่ใช่ที่หน้าจอ
