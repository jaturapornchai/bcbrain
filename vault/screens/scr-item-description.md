# รายละเอียดสินค้า, แก้ด่วนแบบกลุ่ม, กำหนดระดับสินค้า

สามจอเล็กที่อยู่ในไฟล์เดียวกัน (`IcExtraScreens.tsx`) แก้ข้อมูลสินค้าเฉพาะด้าน ทั้งสามเขียนฐานข้อมูลด้วยชุดคำสั่ง SQL ผ่าน `queryExecBatch` (`POST /api/query/execBatch`) โดยตรงจากหน้าจอ ชุดคำสั่งรันในธุรกรรมเดียว ถ้าคำสั่งใดล้มเหลวจะย้อนทั้งชุด (`port.go:100-108`) และ Go ตรวจสิทธิ์ของเมนูจากชนิดคำสั่ง SQL (`permission.go:138-161`) ทั้งสี่เมนูอยู่ที่ สินค้า > ทะเบียนข้อมูลสินค้าและคลังที่เก็บ (`bcMenu.json:1965`, `:1978`, `:2225`, `:2238`) ไม่จำกัดเฉพาะผู้ดูแลระบบ

| รหัส | เมนู | คอมโพเนนต์ | โหมดผูก |
|---|---|---|---|
| 2003 | รายละเอียดสินค้า (`menu_ic_description`) | `ItemDescriptionScreen` | `screenRegistry.tsx:639-650` |
| 2004 | แก้ไขรายละเอียด(เร็ว) (`menu_ic_description_fast`) | `ItemDescriptionFastScreen` | `:651-662` |
| 2023 | กำหนดลำดับการค้นหา (`menu_ic_item_level`) | `ItemLevelScreen` | `:690-701` |
| 2024 | กำหนดลำดับการค้นหา (เร็ว) (`menu_ic_multi_item_level`) | `ItemLevelScreen multi` | `:702-714` |
ชื่อบนจอของ 2023/2024 ดึงจากชื่อเมนูจริง (`getMenuTextByName`) ค่าเริ่มต้นในโค้ดคือ "กำหนดระดับสินค้า" กลไกเมนูดู [[fe-screen-registry-menu]]

## 2003 รายละเอียดสินค้า (`ItemDescriptionScreen`)
เขียนบรรยายสินค้าเป็นข้อความจัดรูปแบบ (HTML) เก็บต่อสินค้า
- ซ้าย: รายการสินค้า (รหัส, ชื่อ, หน่วยนับ) ค้นหาจากรหัส/ชื่อ/หน่วยนับ โหลดสูงสุด 500 แถวเรียงตามรหัส (`useItemLoader`, `:190-288`) เปิดจอแล้วเลือกแถวแรกให้เอง (`:254-262`) ดับเบิลคลิกแถวเข้าโหมดแก้ไข (`:393-396`) ดูกลไกที่ [[scr-data-list-and-lookup]]
- ขวา: การ์ด "ข้อมูลอ้างอิงสินค้า" อ่านอย่างเดียว (รหัส, หน่วยนับ, ชื่อ 1-2, ประเภท, ชนิด, รูปแบบสินค้า, วิธีคำนวณต้นทุน, ประเภทภาษี, กลุ่มสินค้า `:117-187`) แล้วกล่องข้อความ (textarea) สำหรับพิมพ์ข้อความหรือ HTML (`:551-558`) พร้อมแถบเครื่องมือ: รูปแบบบล็อก (ปกติ/H2/H3), ฟอนต์, ขนาด, ตัวหนา, ตัวเอียง, ขีดเส้นใต้, รายการสัญลักษณ์, รายการลำดับเลข (`:467-542`) และปุ่ม Preview สลับดูตัวอย่าง (`:460-466`) ปุ่มจัดรูปแบบเรียก `document.execCommand` แต่ในจอไม่มีองค์ประกอบ contenteditable ที่คำสั่งเหล่านี้จะออกฤทธิ์ได้ (`editorRef` ไม่ได้ผูกกับองค์ประกอบใด `:311`, `:339-343`; ยังไม่ได้ทดสอบบนเบราว์เซอร์) จึงควรถือว่าต้องพิมพ์แท็ก HTML เองแล้วกด Preview ดู ซึ่ง Preview แสดง HTML ตามที่พิมพ์โดยไม่กรองแท็ก (`dangerouslySetInnerHTML`, `:546-549`) ช่องว่างแสดง "กรอกรายละเอียดสินค้าเพิ่มเติม (รองรับข้อความและ HTML)..." ไม่มีรายละเอียดแสดง "ไม่มีรายละเอียด"
- ปุ่ม: โหมดดู = **แก้ไข** (ต้องมีสิทธิ์), **ปิดหน้าจอ**; โหมดแก้ = **บันทึก** (กดได้เมื่อมีสิทธิ์แก้ไข `:440`), **ปิดหน้าจอ** ปุ่มหลังนี้ในโหมดแก้แค่ออกจากโหมดแก้ไข และตั้งข้อความกลับเป็นค่า `ic_inventory.remark` ของสินค้า (`:443-452`) ซึ่งอาจต่างจากค่าใน `ic_description` ถ้าสองที่ไม่ตรงกัน จอนี้ไม่มีคีย์ลัด
- บันทึก (`:345-366`, คำสั่ง `:352-356`) ลบแถวเดิมของสินค้านั้นใน `ic_description` แล้วเพิ่มใหม่ และ **เขียน HTML เดียวกันทับคอลัมน์ `ic_inventory.remark` ด้วย** ในธุรกรรมเดียวกัน; ตอนโหลดถ้ายังไม่มีแถวใน `ic_description` จะใช้ค่า `remark` เดิมมาแสดงแทน (`:321-333`) สำเร็จขึ้น `บันทึกรายละเอียดสินค้า <รหัส> เรียบร้อยแล้ว`
- ข้อควรระวัง: หมายเหตุในส่วน "9.หมายเหตุ" ของ [[scr-item-detail-2]] ใช้คอลัมน์ `remark` ตัวเดียวกัน (ไม่เกิน 255 ตัวอักษร `ItemDetail2Screen.tsx:586-589`, `item_detail.go:57`) ส่วนจอนี้ไม่จำกัดความยาว การบันทึกรายละเอียด HTML จากจอนี้จะทับหมายเหตุนั้น

## 2004 แก้ไขรายละเอียด(เร็ว) (`ItemDescriptionFastScreen`)
แก้ฟิลด์ที่ติ๊กเลือกกับหลายสินค้าพร้อมกัน (รวบรวมเป็นคำสั่ง UPDATE ครั้งเดียวต่อตาราง)
1. กล่อง "รายชื่อสินค้าที่ต้องการแก้ไขพร้อมกัน": ตารางสินค้า (ลำดับ, รหัสสินค้า, ชื่อสินค้า, หน่วยนับ) ย้ายลำดับได้ด้วยปุ่มจับแล้วกดค้างลาก หรือกดลูกศรขึ้น/ลงเมื่อโฟกัสปุ่มจับ (`RowMoveButtons.tsx:236-266`) ลบทีละแถวด้วยไอคอนถังขยะ ปุ่ม **เพิ่มสินค้า** (เปิดหน้าต่าง "เลือกสินค้าเข้าตารางแก้ไขด่วน" `:1316-1335` รหัสที่มีในตารางแล้วจะไม่ถูกเพิ่มซ้ำ) และ **ล้างตารางสินค้า**
   - เปิดจอครั้งแรกตารางไม่ว่าง: ระบบใส่ **10 สินค้าแรกเรียงตามรหัส** ให้เอง (`SELECT ... ORDER BY code ASC LIMIT 10`, `:1053-1067`) ต้องล้างหรือลบเองถ้าไม่ต้องการแก้สินค้าเหล่านั้น
2. 7 ส่วน `FAST_EDIT_TABS` (`:803-1025`) แสดงเรียงต่อกันในหน้าเดียว ปุ่ม "ข้ามไปยังส่วน:" เลื่อนหน้าไปยังส่วนนั้น (`:1207-1227`): 1.ทั่วไป (กลุ่มหลัก, ยี่ห้อ, รูปแบบ, ดีไซน์, หมวด, ระดับ, เกรด, รุ่น, สี, ขนาด) 2.หน่วยนับ/สต็อก (รูปแบบต้นทุน, การควบคุมยอดคงเหลือ, การรับ-จ่าย Serial Number, การคำนวณจุดสั่งซื้อ, ปริมาณสั่งซื้อที่เหมาะสม) 3.บัญชี (ผังบัญชีซื้อ, ขายสด, ขายเชื่อ, ต้นทุนขาย) 4.ขาย (ประเภทภาษี, ประเภทการขาย, ห้ามแก้ไขราคาขาย, ห้ามแก้ไขส่วนลด, กำหนดราคากลาง, สถานะป้ายราคา) 5.ซื้อ (เจ้าหนี้หลัก, สินค้าเครื่องดื่ม) 6.การผลิต (ระยะเวลาการผลิต (วัน), ใช้วันหมดอายุ, ควบคุมยอดค้างรับ/ค้างส่ง) 7.POS (คีย์ลัด POS, อนุญาตป้อนราคาขณะขาย, พิมพ์ใบสั่งอาหารแยกต่อหน่วย)
   - ทุกฟิลด์มี checkbox หน้าช่อง: ฟิลด์ที่ไม่ติ๊กจะไม่ถูกแก้ (`:1245-1262`) ฟิลด์ชนิดเลือกค่ามีตัวเลือก 0/1 ฟิลด์ชนิดรหัส (กลุ่ม ยี่ห้อ รูปแบบ ผังบัญชี เจ้าหนี้ ฯลฯ) มีปุ่ม 🔍 เปิดหน้าต่างเลือกรหัสจากตารางนั้น (`:1288-1303`, `:1337-1346`)
3. **บันทึก** (`handleSave`, `:1069-1115`): ต้องมีสิทธิ์แก้; ไม่มีสินค้าในตารางขึ้น "กรุณาเลือกสินค้าอย่างน้อย 1 รายการ"; ไม่ติ๊กฟิลด์ใดขึ้น "กรุณาติ๊กเลือกฟิลด์ที่ต้องการแก้ไขอย่างน้อย 1 ช่อง" ตัวเลข/ตัวเลือกใช้ `decimalSql(..., "0")` ข้อความใช้ `escapeSql`; ฟิลด์ของ `ic_inventory` -> `UPDATE ... WHERE code IN (...)`; ฟิลด์ของ `ic_inventory_detail` -> สร้างแถวว่างให้สินค้าที่ยังไม่มีก่อน แล้วค่อย `UPDATE ... WHERE ic_code IN (...)` ส่งเป็น `queryExecBatch` ชุดเดียว สำเร็จขึ้น `บันทึกการแก้ไขแบบกลุ่ม (N สินค้า, M ฟิลด์) เรียบร้อยแล้ว` หลังบันทึกจอไม่ล้างตารางสินค้าและช่องที่ติ๊กไว้ (`:1107-1115`) กดบันทึกซ้ำจะเขียนทับอีกครั้ง
- ฟิลด์ที่ติ๊กแต่ปล่อยค่าว่างจะเขียนค่าว่างทับ (ข้อความ) หรือ 0 (ตัวเลข/ตัวเลือก) ทุกสินค้าในตาราง

## 2023/2024 กำหนดระดับสินค้า (`ItemLevelScreen`)
กำหนดระดับ 1-4, ราคาแนะนำ, คำแนะนำ และเงื่อนไข 1-4 ต่อบาร์โค้ด
- 2023 (โหมดปกติ): รายการสินค้าซ้าย (เหมือน 2003 โหลด 500 แถว เลือกแถวแรกให้เอง) เลือกสินค้าแล้วตารางด้านขวาแสดงทุกบาร์โค้ดของสินค้านั้น ไม่มีโหมดดู/แก้ไข แก้ช่องในตารางได้ทันที ปุ่มบันทึกกดได้เมื่อมีสิทธิ์แก้ไข (`:1488`, `:1622-1646`)
- 2024 (`multi`): ไม่มีรายการซ้าย มีช่อง **จากรหัสสินค้า** / **ถึงรหัสสินค้า** กดปุ่ม **ประมวลผล** เพื่อโหลดตามช่วงรหัส ตารางโหลดใหม่เองทุกครั้งที่แก้ช่วงรหัสด้วย (`loadLevels` อยู่ใน dependency ของ `useEffect` `:1439-1443`) ปุ่มจึงเป็นการโหลดซ้ำ ถ้าไม่กรอกช่วงจะโหลด 150 แถวแรกของทั้งฐานข้อมูล ช่วงรหัสใช้ลำดับตัวอักษร (`>=` / `<=` `:1398-1399`) และช่องรหัสแปลงเป็นตัวพิมพ์ใหญ่ (`:1512`, `:1520`)
- ตาราง (บาร์โค้ด, รหัสสินค้า, หน่วย, ระดับ 1-4, ราคาแนะนำ, คำแนะนำ, เงื่อนไข 1-4) ดึงจาก `ic_inventory_barcode` เชื่อม `ic_inventory_level` และ `ic_inventory_barcode_condition` เฉพาะบาร์โค้ดที่ไม่ว่าง และ **จำกัด 150 แถว** (`LIMIT 150`, `:1389-1417`) ราคาแนะนำถ้ายังไม่มีระดับจะเติมราคาจากบาร์โค้ด
- **บันทึก** (`:1445-1473`): ทุกแถวที่แสดงถูกลบแล้วเพิ่มใหม่ทั้งหมดใน `ic_inventory_level` และ `ic_inventory_barcode_condition` (ไม่เฉพาะแถวที่แก้ และแถวที่ไม่ได้กรอกระดับ/เงื่อนไขเลยก็ถูกเพิ่มเป็นแถวว่าง `:1450-1462`) จับคู่ด้วยรหัสสินค้ากับบาร์โค้ด ส่งเป็น `queryExecBatch` ชุดเดียว ถ้าไม่มีแถวจะไม่ส่งคำสั่งแต่ยังขึ้นข้อความสำเร็จ 0 รายการ (`:1463-1467`) สำเร็จขึ้น `บันทึกระดับสินค้า N รายการเรียบร้อยแล้ว`
- ข้อควรระวัง: ช่วงรหัสที่มีบาร์โค้ดเกิน 150 แถวจะเห็นแค่ 150 แถวแรกเรียงตามรหัส/บาร์โค้ด ต้องแบ่งช่วงรหัสทำทีละช่วง
