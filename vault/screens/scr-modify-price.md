# ปรับราคาสินค้า (ModifyPriceScreen)

จอปรับราคาสินค้าครั้งละหลายรายการ: ใส่รายการราคา (นำเข้าไฟล์ข้อความ/CSV หรือพิมพ์ลงตาราง) -> ตรวจดูราคาเก่า -> สั่งประมวลผลทั้งชุด หน้าจอแปลงและตรวจรูปแบบวันที่แล้วส่งแถวไป Go `POST /api/process/modifyprice/preview` หรือ `apply` (`ModifyPriceScreen.tsx:189`) ส่วนการหาแถวเดิม การจัดการราคา 0 และการบันทึกประวัติ (`master_logs`) อยู่ฝั่ง Go ดูหัวข้อ "ฝั่ง Go" ราคาในจอเป็นสตริงทั้งหมดไม่แปลงเป็นตัวเลข ดู [[fe-numeric-money]] ตรรกะราคาโดยรวมดู [[proc-price-engine]]

## วิธีเปิด
เมนู 2014 "ปรับราคาสินค้า" (`menu_ic_modify_price`) อยู่ที่ สินค้า > ทะเบียนข้อมูลสินค้าและคลังที่เก็บ (`bcMenu.json:2108`) ไม่จำกัดเฉพาะผู้ดูแลระบบ ผูกจอที่ `screenRegistry.tsx:367-374` กลไกเมนูดู [[fe-screen-registry-menu]]

## โครงจอ
- ซ้าย: รายการสินค้า (รหัสสินค้า, ชื่อสินค้า, หน่วยนับ) โหลดจาก `ic_inventory` ครั้งละ 500 แถวเรียงตามรหัส ค้นด้วยรหัสหรือชื่อ (`queryLimit ... 500`, `:118-128`) ดูกลไกรายการที่ [[scr-data-list-and-lookup]]
  - คลิกสินค้าหนึ่งครั้ง: ถ้าอยู่โหมดแก้ไขและชนิดราคาไม่ใช่ราคาบาร์โค้ด จะ **เติมรหัสสินค้าและหน่วยนับมาตรฐานลงแถวว่างแถวแรกของตาราง** (ไม่มีแถวว่างก็ต่อท้ายเป็นแถวใหม่) นอกโหมดแก้ไขหรือชนิดราคาบาร์โค้ดแค่เลือกแถวเฉย ๆ (`handlePickItem`, `:226-237`)
  - ดับเบิลคลิก (`:262`): ถ้ายังไม่อยู่โหมดแก้ไขและมีสิทธิ์ จะเข้าโหมดแก้ไข แต่ตอนเรียก `handlePickItem` ค่า `isEditing` ในรอบนั้นยังเป็นเดิม จึง **เข้าโหมดแก้ไขอย่างเดียว ไม่เติมแถว**
  - ตอนอยู่โหมดแก้ไขแล้ว การคลิกทุกครั้ง (`BcDataList.tsx:1094`) การเลื่อนด้วยลูกศรและปุ่มแรก/ก่อนหน้า/ถัดไป/สุดท้าย (`:553-569`, `:615-646`) เรียกเลือกแถวทั้งหมด ดังนั้นแต่ละครั้งเติมแถว และดับเบิลคลิกครั้งเดียวมีสองคลิกบวกตัวจัดการดับเบิลคลิก (`:1095-1097`) จึงอาจได้แถวสินค้าเดียวกันซ้ำสูงสุดประมาณสามแถว (อ่านจากโค้ด ยังไม่ได้ลองในเบราว์เซอร์)
  - ปุ่มเพิ่มใหม่ของรายการซ้ายเรียก `startNew` และปุ่มแก้ไขเข้าโหมดแก้ไข (`:260-261`)
- ขวา: แถบเลือก **ชนิดราคา** (radio) เรียงตามนี้: ราคาบาร์โค้ด / ราคาตามสูตร / ราคามาตรฐาน / ราคาทั่วไป (`:314-325`) ค่าเริ่มต้นคือราคามาตรฐานขอบเขตแรก (`:130-131`) เฉพาะราคามาตรฐานและราคาทั่วไปมีขอบเขตให้เลือกอีก 3 แบบ: ราคาขายทั่วไป / ราคาตามกลุ่มลูกค้า / ราคาตามลูกค้า (`SCOPES`, `:53`, `:326-335`) ค่า `kind` ที่ส่งไปเซิร์ฟเวอร์คือ `<standard|general>_<1|2|3>`, `barcode` หรือ `formula` (`:142`) ขณะอยู่โหมดแก้ไขและมีแถวที่กรอกแล้ว radio ทั้งหมดถูกปิด (`:316,322,330`) ต้องล้างตารางก่อนจึงเปลี่ยนชนิดได้
- ช่องติ๊ก "(Option) แก้ไขราคาให้เป็น 0": ถ้าติ๊ก ช่องราคาที่พิมพ์ 0 จะถูกบันทึกเป็น 0 ช่องที่เว้นว่างไม่เปลี่ยนราคา (ข้อความบนจอ `:337-340`) ค่านี้ส่งไปพร้อมแถว (`zeroOption`, `:189`) การจัดการค่า 0 เมื่อไม่ติ๊กตัดสินที่ Go
- แถบสถานะ (`:275-281`): "ประมวลผลล่าสุด <เวลา>" หลังบันทึกสำเร็จ, "N รายการ" (จำนวนแถวที่กรอก), ป้าย "โหมดแก้ไข"
- ตาราง "รายการปรับราคา (n/5000)" (`:345`) คอลัมน์ขึ้นกับชนิดราคา:
  - มาตรฐาน/ทั่วไป: รหัสสินค้า, หน่วยนับ, [กลุ่มลูกค้าหลัก+ย่อย หรือ รหัสลูกค้า ตามขอบเขต], ตั้งแต่วันที่, ถึงวันที่, จากจำนวน, ถึงจำนวน, ประเภทการขาย, ราคาขาย 1, ราคาขาย 2 (`:34-38`, `:48-59`)
  - บาร์โค้ด: บาร์โค้ด, ราคา, ราคาสมาชิก, ราคา 2/สมาชิก 2, ราคา 3/สมาชิก 3, ราคา 4/สมาชิก 4 (`:39-43`)
  - สูตร: รหัสสินค้า, หน่วยนับ, ประเภทการขาย, ประเภทภาษี, ราคา 0-9 (`:44-47`)
  - ท้ายตารางมีอีกสองคอลัมน์ "ราคาเก่า" กับ "ผลตรวจ" (`:375-376`) เติมหลังกดตรวจราคาเก่าหรือบันทึก
  - ช่องวันที่พิมพ์รูปแบบ `วว/ดด/ปปปป` (ข้อความช่วยในช่อง `:399`) ผิดรูปขึ้น `แถวที่ N: <คอลัมน์> "<ค่า>" ต้องเป็นรูปแบบ วว/ดด/ปปปป` (`:163`) และไม่ส่งชุดนี้ไปเซิร์ฟเวอร์เลย; ช่องตัวเลขที่พิมพ์รับเฉพาะ 0-9 จุด และเครื่องหมายลบ (`onNumKey`, `:224`, ใช้ที่ `:402`) ส่วนค่าที่นำเข้าจากไฟล์ไม่ผ่านตัวกรองนี้ (Go ตรวจรูปแบบแทน)

## การนำเข้าไฟล์ (`parseImport`, `:90-104`)
- อ่านไฟล์เป็น UTF-8 ก่อน ถ้าไม่ใช่ UTF-8 ที่ถูกต้องอ่านเป็น windows-874 (`readText`, `:79-87`) ตัดอักขระ BOM ต้นไฟล์และข้ามบรรทัดว่าง (`:91`)
- ตัวคั่นเลือกอัตโนมัติจากบรรทัดแรก: Tab, จุลภาค, อัฒภาค หรือขีดตั้ง (ลำดับตามนี้) ถ้าไม่พบใช้จุลภาค (`:93`) แยกด้วยตัวคั่นตรง ๆ แล้วตัดเครื่องหมายคำพูดหัวท้ายเซลล์ (`:94`) จึงไม่รองรับตัวคั่นที่อยู่ในเครื่องหมายคำพูด
- ถ้าบรรทัดแรกมีเซลล์อย่างน้อยหนึ่งช่องตรงกับ key หรือชื่อไทยบนจอ ถือเป็นหัวตาราง คอลัมน์ที่ไม่รู้จักถูกทิ้ง (`:95-97`) ถ้าไม่มี เรียงค่าตามลำดับคอลัมน์ของชนิดราคาที่เลือกอยู่ (`:98`)
- วันที่ในไฟล์ไม่แปลงตอนนำเข้า แปลงตอนกดตรวจ/บันทึก (`buildPayload`, `:152-180`) รองรับ `วว/ดด/ปปปป` โดยตัวแบ่งเป็น `/` `.` หรือ `-`, รูปแบบ `ปปปป-ดด-วว`, ปี พ.ศ. (ปีมากกว่า 2400 ลบ 543) และปฏิเสธวันที่ที่ไม่มีจริง (`toIsoDate`, `:63-77`)
- นำเข้าต่อท้ายแถวที่กรอกอยู่ (แถวว่างถูกตัด `:211`) ไฟล์ว่างขึ้น "ไม่พบรายการในไฟล์"; รวมกับของเดิมเกิน 5000 แถวขึ้น `นำเข้าได้รวมไม่เกิน 5000 รายการ (ไฟล์นี้ N รายการ)` (`:207-210`); ตารางว่างตอนกดตรวจ/บันทึกขึ้น "ยังไม่มีรายการราคา กรุณานำเข้าไฟล์หรือเพิ่มแถวก่อน" (`:172`); ปรับได้ครั้งละไม่เกิน 5000 รายการ (`MAX_ROWS`, `:29`, `:175-177`)
- ตารางว่างขึ้นคำแนะนำ "กด เพิ่มใหม่ หรือ แก้ไข แล้วนำเข้าไฟล์ราคา ..." (`:384`)

## ฝั่ง Go (`modify_price.go`)
- เส้นทาง `POST /api/process/modifyprice/{preview|apply}` (`router.go:157`, `:198`) ตัวจัดการอยู่ที่ `docpicture_handler.go:112-139` รับ JSON ไม่เกิน 8 MB (`:119`) สิทธิ์: preview = อ่าน, apply = เขียน (เพิ่มหรือแก้ไข) (`permission.go:32,42`)
- ชนิดราคาเป็นตาราง (`:37-46`): `standard_1/2/3` และ `general_1/2/3` = `ic_inventory_price` โดย `price_type` 1 = รายสินค้า, 2 = กลุ่มลูกค้า, 3 = ลูกค้า และ `price_mode` 0 = มาตรฐาน, 1 = ทั่วไป (คอลัมน์ราคา `sale_price1`, `sale_price2`); `barcode` = `ic_inventory_barcode` (คอลัมน์ `price`, `price_member`, `price_2` ถึง `price_member_4`); `formula` = `ic_inventory_price_formula` (`price_0` ถึง `price_9`)
- ตรวจทั้งชุดก่อน: ชนิดราคาไม่รู้จักขึ้น "กรุณาเลือกประเภทราคาที่ต้องการปรับปรุง"; ไม่มีแถวขึ้น "กรุณาอัพโหลดข้อมูลก่อนดำเนินการ"; เกิน 5000 แถวขึ้น "ทำได้ครั้งละไม่เกิน 5000 แถว" (`:87`, `:90`, `:93`)
- ตรวจรายแถว ไม่ผ่านแถวใดแถวนั้นถูกข้ามพร้อมเหตุผลและไม่ล้มทั้งชุด (`planModifyPrice`, `:154-167`): รหัสสินค้า หน่วยนับ บาร์โค้ด รหัสกลุ่ม/ลูกค้ายาวเกิน 50 ตัวอักษร (`:196-200`); ชนิดบาร์โค้ดต้องมีบาร์โค้ด ขึ้น "ไม่มีบาร์โค้ด" (`:204`) ชนิดอื่นต้องมีทั้งรหัสสินค้าและหน่วยนับ ขึ้น "ต้องมีรหัสสินค้าและหน่วยนับ" (`:207`); ประเภทการขายและประเภทภาษีถ้ากรอกต้องเป็นจำนวนเต็ม 0-32767 (`:214-221`); ราคา จากจำนวน ถึงจำนวนต้องเป็นทศนิยมที่ถูกต้อง (ตัดเครื่องหมายจุลภาคให้ก่อน, `normDecimal`, `barcode.go:110-119`); สินค้าที่ไม่มีใน `ic_inventory` ขึ้น "ไม่พบสินค้า X" (`:160-161`) โดยตรวจรหัสทั้งชุดด้วยคำสั่งเดียว (`:124-143`) เว้นชนิดบาร์โค้ด
- วันที่และจำนวน (เฉพาะ `ic_inventory_price`): วันที่ใช้เมื่อกรอกครบทั้งตั้งแต่และถึง ถ้ากรอกข้างเดียว Go ไม่นำมาใช้โดยไม่แจ้ง (`:223-231`); จำนวนใช้เมื่อทั้งสองช่องไม่เป็น 0 (`:232-242`)
- การหาแถวเดิม (`match`, `:260-301`): ชนิดบาร์โค้ดหาจากบาร์โค้ดอย่างเดียว ชนิดอื่นหาจากรหัสสินค้า + หน่วยนับ (+ `price_type` + `price_mode` ของราคาสินค้า) และเงื่อนไขเสริมเฉพาะช่องที่กรอก: กลุ่มลูกค้า/รหัสลูกค้า ประเภทการขาย (สูตรเพิ่มประเภทภาษี) ช่วงวันที่ ช่วงจำนวน เลือกแถวแรกตามลำดับ `roworder` เท่านั้น (`:308`) ราคาเก่าที่แสดงคือคอลัมน์ราคาแรกของชนิด: `sale_price1`, `price` หรือ `price_0` (`:304`)
- ผลต่อแถว (`:315-324`): ไม่มีราคาที่จะเขียน (ว่างทั้งหมด หรือเป็น 0 โดยไม่ติ๊กตัวเลือก) = ข้าม "ไม่มีราคาที่ต้องแก้ไข ..." (`:250-254`, `:317`); ชนิดบาร์โค้ดไม่พบบาร์โค้ด = ข้าม "ไม่พบบาร์โค้ด X" (`:319`) ชนิดบาร์โค้ดจึงแก้ได้อย่างเดียว ไม่เพิ่มบาร์โค้ดใหม่; พบแถวเดิม = แก้ไขเฉพาะคอลัมน์ราคาที่กรอก (`:328-337`); ไม่พบ = เพิ่มราคาใหม่
- ตอนเพิ่มราคาใหม่ใน `ic_inventory_price` ถ้าไม่ได้กรอก ใช้ค่าเริ่มต้นจำนวน 1 ถึง 999999 และวันที่ 1 ม.ค. ถึง 31 ธ.ค. ของปีปัจจุบัน (`:369-380`) ประเภทการขาย (และประเภทภาษีของสูตร) ที่กรอกถูกบันทึกด้วย (`:383-388`)
- ตรวจราคาเก่าทำในธุรกรรมอ่านอย่างเดียว ไม่เขียนอะไร (`:101-103`) ส่วนบันทึกล็อกงานนี้ทีละครั้งด้วย advisory lock (`:105-110`) ทำทุกแถวแล้วเขียนประวัติหนึ่งแถวลง `master_logs` (function_code 1, menu_name `ModifyPrice`, เก็บชนิด ตัวเลือก 0 แถวที่ส่ง และผลรายแถวเป็น JSON) ในธุรกรรมเดียวกัน (`:115-117`, `:395-406`) ข้อผิดพลาดของระบบทำให้ยกเลิกทั้งชุด แต่แถวที่ถูกข้ามไม่ทำให้ยกเลิก

## ตารางที่เกี่ยวข้อง
ตารางที่จอเขียนผ่านเซิร์ฟเวอร์ตามชนิดราคา (ตัวจอไม่เขียนตารางเอง): [[tbl-ic-inventory-price]] (ราคามาตรฐาน/ทั่วไป ตามสินค้า กลุ่มลูกค้า ลูกค้า) และ [[tbl-ic-inventory-barcode]] (ราคาบาร์โค้ด) ส่วนราคาตามสูตรเก็บใน `ic_inventory_price_formula` และประวัติใน `master_logs` ซึ่งยังไม่มีโน้ตตารางในคลังนี้ การตรวจสินค้าอ่านจาก [[tbl-ic-inventory]] (ไม่ใช่ตารางส่วนลดตามบาร์โค้ด [[tbl-ic-inventory-barcode-price]] ซึ่งเขียนโดยจอ [[scr-barcode-discount]])

## ข้อควรระวัง
- ปุ่ม "ตรวจราคาเก่า" ควรกดก่อนบันทึกทุกครั้ง เพราะผลแสดงว่าแถวไหนถูกข้าม และแถวไหนจะ "เพิ่มราคาใหม่" แทนที่จะแก้ของเดิม (เช่นสะกดหน่วยนับหรือประเภทการขายต่างจากแถวเดิม Go จะเพิ่มแถวราคาใหม่) เหตุผลที่แสดงมาจากเซิร์ฟเวอร์ ไม่ได้กำหนดในหน้าจอ
- การเปลี่ยนค่าใดในตาราง ตัวเลือก 0 หรือชนิดราคาจะล้างผลตรวจเดิม ต้องกดตรวจใหม่ (`setPlans({})`, `:148`, `:223`, `:338`)
- ผลตรวจผูกกับลำดับแถวบนจอ ไม่ใช่รหัสสินค้า: Go นับเฉพาะแถวที่กรอก แล้วหน้าจอแปลงกลับเป็นตำแหน่งแถวเดิม (`:154-169`, `:193`)
- ปุ่ม **ลบ** ล้างเฉพาะรายการบนหน้าจอ ไม่ได้ลบราคาในฐานข้อมูล และจอนี้ไม่มีฟังก์ชันลบราคาจากฐานข้อมูลเลย
- ถ้ามีหลายแถวในฐานข้อมูลที่ตรงเงื่อนไขเดียวกัน (เช่นไม่กรอกช่วงวันที่หรือจำนวน) Go แก้เฉพาะแถวแรกตาม `roworder`
- ดับเบิลคลิกรายการซ้ายขณะอยู่โหมดแก้ไขอาจเติมแถวสินค้าเดียวกันซ้ำ ควรลบแถวส่วนเกินก่อนบันทึก
