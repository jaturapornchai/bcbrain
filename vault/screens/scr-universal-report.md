# จอรายงานกลาง (UniversalReportScreen)

หน้าจอเดียวที่แสดงรายงานของเมนูใบกลุ่มรายงานและสอบถามเกือบทั้งหมด ณ โค้ดชุดนี้นับได้ 366 ใบ (วิธีนับอยู่ในหัวข้อ "วิธีเปิดและจำนวนเมนู") ตั้งแต่รายงานสินค้า ซื้อ ขาย เจ้าหนี้ ลูกหนี้ เงินสด/ธนาคาร/เช็ค สินทรัพย์ ไปจนถึงบัญชีแยกประเภท ผู้ใช้เห็นแถบเงื่อนไขด้านบน กดประมวลผล แล้วได้ตารางผลลัพธ์ที่มีหัวกลุ่ม ยอดรวม และปุ่มพิมพ์

หน้าจอนี้ไม่คำนวณรายงานเอง: คอลัมน์ แถว ยอดรวม โครงสร้างกลุ่ม และเงื่อนไขที่ต้องกรอก มาจาก backend ผ่าน `POST /api/process/report/run` (`runBackendReport`, `frontend/src/lib/query-client.ts:1020-1023`) เอกสารนี้อธิบายมุมมองผู้ใช้ ส่วนกลไกจ่ายงานฝั่ง backend และตารางกฎเลือกโหมดอยู่ที่ [[fe-report-screens]] (ไม่ทำซ้ำที่นี่) เลขบรรทัดที่ไม่ระบุไฟล์ในเอกสารนี้เป็นของ `frontend/account/report/UniversalReportScreen.tsx`

## วิธีเปิดและจำนวนเมนู

- ไม่มีไฟล์หน้าจอต่อรายงาน: `registerAllMenus` ไล่ใบเมนูทุกใบ (`screenRegistry.tsx:1382-1402`) ใบที่ยังไม่มีจอลงทะเบียนตรงชื่อจะเข้า `buildDynamicScreen` (`screenRegistry.tsx:1067`) ซึ่งตรวจกฎเป็นลำดับ (เอกสารซื้อขายตาม `transMenuMap` ก่อน แล้วจอกระบวนการต่าง ๆ) ใบที่ไม่เข้ากฎก่อนหน้าจะกลายเป็นจอรายงาน โดยเลือกโหมดจากสาขาเมนูบนสุด (`topBranchName`, `screenRegistry.tsx:1332-1378`) ภาพรวมการลงทะเบียนอยู่ที่ [[fe-screen-registry-menu]]

- ตัวเลขข้างบนได้จากการไล่ทุกใบเมนูของ `bcMenu.json` (700 ใบหลังกรองรุ่น ดู [[fe-screen-registry-menu]]) ตามกฎเดียวกับ `buildDynamicScreen` ไม่ได้เก็บเป็นค่าคงที่ในโค้ด จึงเปลี่ยนเมื่อเพิ่มหรือย้ายเมนู รายการเมนูเต็มอยู่ที่ [[screens-overview]]

## แถบชื่อและปุ่มเครื่องมือ

- แถบหัว: "หน้าจอรายงานและการประมวลผลข้อมูล (Backend Report Engine)" (`:1098`) และ "พบข้อมูล N รายการ" ต่อด้วย "(N ms)" เมื่อ backend รายงานเวลาประมวลผลมากกว่า 0 (`:1104-1105`) ข้อความสถานะสีเขียวแสดงผลการกระทำในแผงออกแบบ (`:1100-1102`) เช่น "รันคำสั่ง SQL On-The-Fly สำเร็จแล้ว" (`:610`), "คืนค่าคอลัมน์และความกว้าง % เริ่มต้นแล้ว" (`:638`), "ใช้รูปแบบรายงานมาตรฐานระบบ" (`:756`), "ตั้งเป็นรูปแบบรายงานเริ่มต้น (Default) เรียบร้อยแล้ว" (`:809`)
- แถวปุ่ม (`:1117-1186`):
  - "ประมวลผลรายงาน" (`:1122`) ปิดระหว่างโหลด
  - "ส่งออก CSV" (`:1131`) ปิดเมื่อไม่มีแถว
  - "พิมพ์รายงาน" (`:1139`) เปิด [[scr-report-print-modal]] (`handlePrintPdf` `:812`, หน้าต่างอยู่ที่ `:2421-2440`)
  - "ปรับคอลัมน์ % / ซ่อนคอลัมน์" (`:1147`), "SQL Query On-The-Fly" (`:1155`), "รูปแบบรายงาน (n)" (`:1163`, n = จำนวนรูปแบบที่บันทึกไว้)
  - ปุ่มวิเคราะห์ด้วย AI (`:1168-1176`, `data-testid="ai-report-analyze-btn"`) ปิดและเปลี่ยนข้อความเป็น "AI กำลังวิเคราะห์..." ระหว่างโหลด
  - "ปิดหน้าจอ" (`:1182`) แสดงเมื่อมี `onClose` เท่านั้น
- ตรงกลางมุมขวาของแถบ มีรหัสเมนูและชื่อรายงาน ถ้าตั้งหัวรายงานเองในแผงรูปแบบ จะแสดงชื่อที่ตั้งแทนชื่อเมนู (`:1188-1195`, ใช้ `printSettings.customTitle`)
- ปุ่มคอลัมน์ / SQL / รูปแบบเป็นสวิตช์: กดซ้ำที่แท็บเดิมจะปิดแผงออกแบบ (`handleOpenStudioTab` `:589-596`) แผงเปิดอยู่แล้วตั้งแต่เข้าจอสำหรับโหมด `sql_utility` ยกเว้นเมนูที่ชื่อมี `database_struct` (1103) ซึ่งเปิดมาแบบปิดแผง และแท็บเริ่มต้นของโหมด `sql_utility` คือแท็บ SQL ส่วนโหมดอื่นเริ่มที่แท็บคอลัมน์ (`:186-193`) รายละเอียดแผงอยู่ในหัวข้อ `GlobalReportStudioPanel` ของ [[scr-report-print-modal]]

## ผลลัพธ์บนหน้าจอ

1. **เปิดจอแล้วรันรายงานให้เองทันที** ไม่ต้องกดประมวลผล (`useEffect` `:569-585`) ถ้ารอบแรก backend แจ้งว่าเมนูนี้ตั้งให้แสดงรายละเอียดเป็นค่าตั้งต้น (`detailDefault`, คืนค่าที่ `:528`) จอจะสลับเป็นโหมดรายละเอียดและรันซ้ำด้วยคำขอเดิม
2. แถบสรุป "โครงสร้างรายงาน BC Account" (`:1434`) แสดงเมื่อมีชนิดรายงานหรือการ์ดสรุป (`reportCategory || summaryCards.length > 0` `:1429`) การ์ด KPI จาก backend จัดรูปแบบตัวเลขด้วย `formatMoneyDisplay` ตามทศนิยมของยอดเงิน ยกเว้นหน่วย "รายการ" (`:1464-1469`) ดู [[fe-numeric-money]]
3. **การ์ด AI** (กดปุ่มวิเคราะห์): ส่ง `rows` ทั้งหมด `totals` และ `summaryCards` ไปที่ `POST /api/process/workflow/ai-report-analyze` โดยไม่ตัดจำนวนแถว (`handleAnalyzeReportWithAi` `:229-256`) การ์ด (`:1489-1560`) มีหัวข้อสรุป "ประเด็นสำคัญและจุดเด่น (Key Highlights)" "ข้อสังเกตและจุดที่ควรตรวจสอบ (Anomalies & Risks)" และปุ่ม "ซ่อนบทวิเคราะห์" (`:1510`) ถ้า AI ล้มเหลวขึ้น "AI วิเคราะห์รายงานไม่สำเร็จ" ในแถบข้อผิดพลาด (`:1483`)
4. **แถบควบคุมรายงานหลายชั้น "Engine รายงานหลายชั้น (Multi-Level)"** (`:1562-1668`) แสดงทุกครั้งที่มีแถวข้อมูล (`rows.length > 0` `:1563`) แต่ส่วนประกอบข้างในต่างกันตามสถานะ:
   - "ชั้นที่ 1" (`:1572-1594`) ตัวเลือก 3 แบบ: อัตโนมัติตามโครงสร้างที่ backend ส่งมา (ต่อท้ายชื่อคอลัมน์กุญแจของชั้นแรกเมื่อยังไม่ได้เลือกเอง), "ตารางชั้นเดียว (ไม่แยกหัวกลุ่ม)" (ค่า `__flat__`) หรือ "แยกชั้นที่ 1 ตาม: <คอลัมน์>"
   - "ชั้นที่ 2" (`:1596-1626`) แสดงเมื่อชั้นที่ 1 ไม่ใช่ตารางชั้นเดียว มีตัวเลือก "-- แสดงรายการเคลื่อนไหว/รายละเอียดทันที --" หรือ "แยกชั้นที่ 2 ตาม: <คอลัมน์>"
   - ช่องติ๊ก "ซ่อนคอลัมน์หัวกลุ่มซ้ำในแถวรายละเอียด" (ค่าเริ่มต้นติ๊ก `:169`) ตัวนับ "N กลุ่ม · N รายการย่อย" และปุ่ม "กางทั้งหมด" / "ยุบดูเฉพาะสรุปหัวกลุ่ม" แสดงเมื่อโครงสร้างหลายชั้นทำงานอยู่ (`isMultiLevelActive` `:853-856`, ส่วนควบคุม `:1628-1666`)
   - การเปลี่ยนชั้น 1 หรือชั้น 2 **ส่งไป backend ประมวลผลใหม่** ไม่ใช่จัดกลุ่มในเบราว์เซอร์ (`handleUpdatePrintSettings` `:668-692`) ค่าเก็บในการตั้งค่าพิมพ์ร่วม จึงมีผลกับ PDF ด้วย
5. **ตาราง** (`:1672-2420`):
   - คอลัมน์ "ลำดับ" (`:1722`) แล้วตามด้วยคอลัมน์ที่ backend ส่งมา ลากขอบหัวคอลัมน์เพื่อปรับสัดส่วน % (ป้าย "ลากซ้าย-ขวาเพื่อปรับสัดส่วน % ความกว้างคอลัมน์" `:1790`) ถ้าผลรวม % เกิน 100 ตารางจะกว้างเกินจอและเลื่อนแนวนอนได้ (`:954-960`) เมื่อตารางกว้างเกินจอ หัวคอลัมน์สุดท้ายมีปุ่มเล็กสองปุ่ม: จัดความกว้างคอลัมน์อัตโนมัติให้พอดีกับข้อมูล และคืนค่าคอลัมน์กับความกว้างเริ่มต้น (`:1762-1784`)
   - แถวที่เซลล์เลขที่เอกสาร ประเภทรายวัน หรือรายละเอียดเป็น "ยอดยกมา" จัดรูปเป็นแถวพิเศษ (`:1826-1828`, `:1900-1902`) และแถวข้อความขึ้นต้น "รวม :" ถือเป็นแถวยอดรวมของ backend (`:1857`)
   - โหมดหลายชั้น: คลิกที่หัวกลุ่มเพื่อพับ/กาง (`:2126`, ชั้นที่ 2 `:2216`) หัวกลุ่มแสดงจำนวน "N รายการเคลื่อนไหว" (`:2163`) และ "ยอดยกมา:" ของกลุ่ม (`:2170`) ท้ายกลุ่มแสดง "รวม<คำนำ> <กุญแจกลุ่ม> (N รายการ)" (ชั้นที่ 2 `:2263`, ชั้นที่ 1 `:2283`)
   - ไม่มีข้อมูลขึ้น "ไม่พบข้อมูลตามเงื่อนไขที่ระบุ" (`:2332`) ท้ายตารางมีแถวยอดรวม "รวมทั้งสิ้น (N รายการ)" (`:2379`) เมื่อมีแถวและมียอดรวมจาก backend (`:2338`)
6. เลือกภาษารายงานเป็น English ในแผงตั้งค่า จะแปลหัวข้อ ป้ายคอลัมน์ และข้อความคงที่ของหน้าจอเป็นอังกฤษด้วย (`isReportEn` `:212-215`)

## การแสดงผลทีละส่วน (ประสิทธิภาพ)

เบราว์เซอร์วาดทีละ 80 แถว (หรือ 40 กลุ่มในโหมดหลายชั้น) (`:200-203`) เลื่อนลงจนเหลือไม่เกิน 320 px ถึงท้ายตารางจึงเพิ่มอีก 150 แถว (หรือ 60 กลุ่ม) (`handleTableScroll` `:1077-1090`) หรือกดปุ่ม "โหลดเพิ่ม +250 รายการ" / "โหลดเพิ่ม +80 กลุ่ม" และ "แสดงทั้งหมด (N รายการ)" / "แสดงทั้งหมด (N กลุ่ม)" ในแถบท้ายตาราง (`:2045-2063`, `:2302-2320`) ทุกครั้งที่ประมวลผลใหม่ จำนวนที่วาดถูกรีเซ็ตกลับ 80 / 40 (`:424-425`)

## ส่งออก CSV

สร้างไฟล์ในเบราว์เซอร์จากคอลัมน์ที่มองเห็นและทุกแถวใน `rows` (ไม่ใช่เฉพาะแถวที่วาดแล้ว) ชื่อไฟล์ `<menuKey>_<วันนี้>.csv` นำหน้าด้วย BOM `\uFEFF` เพื่อให้ Excel อ่านภาษาไทยได้ ค่าในเซลล์ใส่เครื่องหมายคำพูดและ escape `"` แต่หัวคอลัมน์ไม่ใส่เครื่องหมายคำพูด จึงเสียหลักถ้าป้ายคอลัมน์มีเครื่องหมายจุลภาค (`handleExportCsv` `:1052-1071`) ปุ่มปิดเมื่อไม่มีแถว

- ไม่มีทางกดจากแถวรายงานไปเปิดเอกสารต้นทาง ผู้ใช้ต้องจดเลขที่เอกสารแล้วไปเปิดเองที่จอทรานแซกชัน ([[scr-universal-trans]])
