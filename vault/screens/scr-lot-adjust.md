# ปรับปรุงสต็อกอัตโนมัติจากใบตรวจนับ / ปรับมูลค่า Lot คงค้าง

สามเมนูอยู่ในเมนู สินค้า > ตรวจนับสต็อกและปรับปรุงจากการตรวจนับ (`bcMenu.json:2475`) ในหมวดย่อย "② ประมวลผลปรับปรุงสต็อกจากใบตรวจนับ" (ช่อง `section` ของแต่ละเมนู `bcMenu.json:2526`, `:2539`, `:2552`) ไม่ใช่เมนูเฉพาะแอดมิน (ไม่อยู่ใน `ADMIN_ONLY_MENU_SET` ของ `bcMenu.ts:315-390`) สร้าง "ใบปรับปรุงสต็อก" ให้เอง **หน้าจอส่งไปเฉพาะเลขที่ใบนับ รูปแบบเลขที่ และกุญแจของ LOT ที่ติ๊ก ส่วนปริมาณและมูลค่าทุกบรรทัด Go อ่านจากฐานข้อมูลแล้วคำนวณเอง** (`LotAdjustScreens.tsx:663-668`, `:139-140`; `stock_lot.go:617-788`, `:387-460`) ตรรกะอยู่ที่ [[proc-stock-tools]] และ [[api-proc-actions-stock]]

ใบที่ได้เป็นสองแบบ (ค่าคงที่ `stock_lot.go:29-30`): **ปรับเพิ่ม** (รูปแบบเอกสาร IA, ประเภท 66 [[doc-stock-adjust-increase]]) และ **ปรับลด** (IS, ประเภท 68 [[doc-stock-adjust-decrease]]) ส่วนต้นทางของ 2045/2046 คือเอกสารนับสต็อก ประเภท 76 [[doc-stock-count]] (`stock_lot.go:499`, `:571`)

## 2045 / 2046 ปรับปรุงสต็อกอัตโนมัติ (`StockAutoAdjustLotScreen`, `:537-943`)
จอแบ่งซ้าย-ขวา (`ResizableSplit` `:706-711`): ซ้ายเป็นรายการใบนับ ([[scr-data-list-and-lookup]]) ขวาเป็นแถบเงื่อนไข ตารางเลือกใบนับ ตารางรายการ และแถบคำสั่งล่าง ผลของการประมวลผลคือใบปรับเพิ่ม/ลดที่ผูกกับใบนับที่เลือก

- **2045 (normal)** ส่ง `ignoreLot: true` (`:667`) ใช้ยอดนับรวมตามคลัง/ที่เก็บ ไม่แยก LOT **2046 (lot)** ส่ง `ignoreLot: false` ใช้ LOT ของแต่ละบรรทัดนับ ตารางรายการจึงมีคอลัมน์ LOT เฉพาะ 2046 (`CHECK_COLS_LOT` `:60-71`) หัวตารางบนบอกโหมดว่า "สร้างเอกสารปรับปรุงสต็อกตามผลต่างคลัง/ที่เก็บ" หรือ "...ตามผลต่างของ LOT" (`:836`)
- **แถบเงื่อนไข** (`:772-830`): **จากวันที่** ค่าเริ่มต้นคือวันที่ 1 มกราคมของปีปัจจุบัน (`:541-542`, ฟังก์ชันชื่อ `monthStart` แต่คืนค่า `YYYY-01-01`) **ถึงวันที่** คือวันนี้ (`:543`), **รหัสเอกสาร** ปรับเพิ่ม (IA) และ **รหัสเอกสารปรับปรุงลด** (IS) เป็นรายการเลือกที่อ่านรูปแบบเลขที่จาก [[tbl-erp-doc-format]] ผ่าน `/api/process/stocktools/formats` (`StockToolBits.tsx:22-33`) ปุ่มค้นข้างช่องเปิดกล่อง "เลือกรูปแบบเอกสาร" (`DocFormatPickerModal` `:464-535`; ไม่มีรูปแบบขึ้น "ไม่พบรูปแบบเอกสาร IA/IS ในระบบ (ระบบจะสร้างเลขที่อัตโนมัติ)" `:505`) ช่อง "รูปแบบเอกสาร" แสดงรูปแบบเลขที่ของ IA อ่านอย่างเดียว (`:791-799`) และติ๊ก **แสดงทั้งหมด** ("รวมเอกสารนับที่ปรับปรุงแล้ว") จะโหลดใหม่ทันที (`:817-830`) จอตั้งต้นเลือกรูปแบบแรกของแต่ละประเภทให้เอง (`:567-577`)
- **โหลดใบนับ** (`load` `:599-619`, เรียกตอนเปิดจอ `:621-624`): `POST /api/process/stocktools/lotautolist` ด้วย `{dateBegin, dateEnd, showAll}` Go คืนใบนับประเภท 76 ที่ไม่ถูกยกเลิก (`last_status = 0`) และ `doc_success = 0` ในช่วงวันที่ ถ้าไม่ติ๊ก "แสดงทั้งหมด" จะตัดใบที่มีใบปรับ (ประเภท 66/68) ที่ยังไม่ถูกยกเลิกผูกอยู่ออก เรียงตามวันที่ เวลา เลขที่ และส่งไม่เกิน 2001 ใบ (`stock_lot.go:481-515`, เงื่อนไขการผูก `:157-160`) ตารางบนแสดง เอกสารวันที่, เวลา, เลขที่, อ้างอิงวันที่, อ้างอิง, หมายเหตุ, สถานะ ("ปรับปรุงแล้ว" / "ยังไม่ได้ปรับ" `AUTO_COLS` `:37-45`, `:699`) ใบที่ยังไม่ปรับถูกติ๊กไว้ให้ทั้งหมด ใบที่ปรับแล้วติ๊กไม่ได้และไม่นับในการประมวลผล (`docNos` นับเฉพาะ `!processed` `:582`) สถานะล่างขึ้น `พบเอกสารตรวจนับ N ใบ`
- **รายการซ้าย**: คลิกหรือเลื่อนแถวเลือกใบ จะ **ติ๊กใบนั้นให้อัตโนมัติ** (ถ้ายังไม่ปรับ) และโหลดรายการในใบนั้นลงตารางล่าง (`:724-734`) ปุ่มค้นในรายการซ้ายเรียก `load` ใหม่ (`:737`)
- **ตารางล่าง "ตารางรายการ"** (`:854-877`): รายการในใบนับที่ติ๊ก (`lotautocheck`, `onlyDuplicate: false` `:584-597`) คอลัมน์ เอกสารวันที่, เวลา, เลขที่, รหัสสินค้า, ชื่อสินค้า, หน่วยนับ, คลัง, พื้นที่เก็บ, (LOT เฉพาะ 2046), จำนวน Go ส่งไม่เกิน 2000 บรรทัด เรียงตามรหัสสินค้า (`stock_lot.go:567-573`) ลิงก์ "แสดงรายการทั้งหมดในใบตรวจนับที่เลือก" โหลดซ้ำ (`:859-868`)
- **ปุ่มบน**: **Load** · **เลือกรูปแบบเอกสาร** (เปิดกล่อง IA) · **เลือกทั้งหมด** (เฉพาะใบยังไม่ปรับ `:629-632`) · **ไม่เลือกทั้งหมด** · **ปิดหน้าจอ** (`:754-766`) **ปุ่มล่าง** (`:882-903`): **ตรวจสอบสินค้าซ้ำ** · **สินค้าที่ไม่มีการตรวจนับและมียอดคงเหลือ** · **ประมวลผล** (ปิดเมื่อไม่ได้ติ๊กใบ) · **Stop** (เปิดเฉพาะตอนจอไม่ว่าง)
- **ตรวจสอบสินค้าซ้ำ** (`checkDuplicate` `:639-655`): ใช้ใบที่ติ๊ก ถ้าไม่ได้ติ๊กจะใช้ทุกใบในตาราง ส่ง `onlyDuplicate: true` Go คืนบรรทัดของสินค้าที่ปรากฏมากกว่า 1 บรรทัดในใบที่เลือก นับตามรหัสสินค้าอย่างเดียว ไม่แยกคลัง/ที่เก็บ/LOT (`stock_lot.go:562-566`) สถานะขึ้น `พบสินค้าซ้ำ N รายการ`
- **ประมวลผล** (`ask` `:690-693`, Ctrl+S ผูกที่ `useShortcuts(ask, null, true)` `:694`, `ScreenFrame.tsx:37-59`): ไม่มีสิทธิ์เพิ่ม/แก้ขึ้น `คุณไม่มีสิทธิ์ "เพิ่ม/แก้ไขข้อมูล" ...`; ไม่ได้ติ๊กใบที่ยังไม่ปรับขึ้น "กรุณาเลือกเอกสารนับสต็อกที่ยังไม่ได้ปรับปรุง" (`:626-627`); แล้วถามยืนยัน `ต้องการทำการประมวลผล ปรับปรุงสต็อกสินค้า/วัตถุดิบ (N ใบ) หรือไม่` (`:940`) ยืนยันแล้ว `POST /api/process/stocktools/lotautorun` ด้วย `{docNos, docFormatCode, downDocFormatCode, ignoreLot}` (`run` `:657-682`) ผลขึ้นข้อความรวม เช่น `ปรับเพิ่ม <เลขที่> (N รายการ) · ปรับลด <เลขที่> (M รายการ)` หรือ "ไม่มีรายการที่ต้องปรับปรุง" และ `ข้าม N รายการ...` (`resultText` `:82-84`) แล้วโหลดตารางใหม่ ข้อความสถานะ: "Start Process..." -> "Process Success!!"
- **Stop ไม่ได้ยกเลิกงานที่เซิร์ฟเวอร์**: `stopProcess` แค่ตั้งธงและปลดสถานะ busy ที่หน้าจอ แล้วไม่แสดงผลลัพธ์เมื่อคำขอกลับมา (`:684-689`, `:670-673`) ไม่มี `AbortController` คำขอที่ส่งไปแล้วจึงอาจสร้างใบปรับจริง ถ้ากด Stop ให้กด Load ตรวจสถานะใบนับ ("ปรับปรุงแล้ว") ก่อนประมวลผลซ้ำ ฝั่ง Go กันการปรับซ้ำไว้ (ดูหัวข้อถัดไป)

### สิ่งที่ Go ทำเมื่อกดประมวลผล (`LotAutoRun`, `stock_lot.go:617-788`)
ทั้งหมดอยู่ในธุรกรรมเดียวที่มีเวลาจำกัด 60 วินาที (`trans.go:446-469`) ล้มตรงไหนย้อนทั้งหมด และใช้ advisory lock กันสองคำขอรันพร้อมกัน (`:162-167`, `:624`)
1. เลือกใบนับได้ 1-200 ใบ (`cleanDocNos` `:536-548`) ใบที่ไม่พบหรือถูกยกเลิกทำให้ล้มทั้งชุด (`:654-656`) ใบที่มีใบปรับที่ยังไม่ถูกยกเลิกผูกอยู่แล้วถูกปฏิเสธพร้อมข้อความให้ยกเลิกใบปรับก่อน (`:644-647`) การกดซ้ำจึงไม่ปรับสองรอบ ถ้าต้องการปรับใหม่ต้องยกเลิกใบปรับเดิมก่อน ดู [[proc-doc-cancel-approve]]
2. **วันที่และเวลาของใบปรับ** ใช้ของใบนับที่ใหม่ที่สุดในชุดที่เลือก ไม่ใช่วันนี้ ถ้าใบนั้นไม่มีเวลาใช้ 23:59 (`:657-660`)
3. **ยอดนับ** รวมจากบรรทัดของใบนับทุกใบที่เลือก ตามกลุ่ม สินค้า + คลัง + ที่เก็บ + LOT แปลงเป็นหน่วยฐานด้วย `stand_value / divide_value` (`:667-671`) ถ้านับสินค้าเดียวกันซ้ำหลายบรรทัด ยอดถูกบวกรวมกัน ไม่ได้ใช้บรรทัดล่าสุด (จึงมีปุ่มตรวจสอบสินค้าซ้ำ) 2045 ตัด LOT ทิ้ง (`lotCol = ''` `:663-666`) ใบนับที่ไม่มีรายการสินค้าขึ้น "เอกสารตรวจนับที่เลือกไม่มีรายการสินค้า" (`:675-677`) และสินค้าที่ไม่มีในทะเบียนขึ้น "ไม่พบรหัสสินค้า ... ในทะเบียนสินค้า" (`:690-694`)
4. **ยอดในระบบ ณ วันที่ของใบปรับ** อ่านแบบกว้าง: ชุดสินค้า x ชุดคลัง x ชุดที่เก็บ ที่ปรากฏในใบนับ ไขว้กันทุกคู่ (`= ANY` แยกกันสามเงื่อนไข `:698-704`) 2046 อ่านยอดรายแถว LOT จาก [[tbl-ic-trans-detail-lot]] แล้วเติมแถวไม่มี LOT สำหรับยอดคลัง/ที่เก็บส่วนที่ LOT อธิบายไม่ได้ (`lotBalanceRows` `:109-137`, `:708-725`)
5. **ผลต่าง** (`processLotDiff` `:79-103`): ทุกกลุ่มที่นับ ปรับให้เท่ายอดนับ (นับมากกว่า = ปรับเพิ่ม, น้อยกว่า = ปรับลด, ไม่มีในระบบ = เพิ่มเท่ายอดนับ) ส่วนแถวยอดในระบบที่ไม่มีใครนับ (ในชุดไขว้ด้านบน) **ถูกปรับให้เป็น 0** ปัดผลต่างที่ทศนิยม 4 ตำแหน่ง ไม่มีผลต่างเลยจะไม่สร้างเอกสาร (`:728-731`) ผลต่างเกิน 5000 รายการให้เลือกใบทีละส่วน (`:732-734`)
6. **ราคาต่อหน่วย** ของทุกบรรทัดตั้งเป็นต้นทุนเฉลี่ย `ic_inventory.average_cost` ปัจจุบัน มูลค่า = จำนวน x ต้นทุนเฉลี่ย ปัด 2 ตำแหน่ง (`:738-742`, `:252`) ดู [[tbl-ic-inventory]] ต้นทุนจริงของบรรทัดลดถูกคำนวณใหม่ตอนสร้างสต็อก ดู [[flow-stock-movement-cost]]
7. **เลขที่เอกสาร** จัดสรรจากรูปแบบ IA แล้วตรวจให้ทั้ง `N` (ประเภท 66) และ `-N` (ประเภท 68) ยังไม่ถูกใช้ ถ้าใช้แล้วเพิ่มเลขท้ายทีละ 1 (`freeAdjustNo` `:171-190`) ใบปรับเพิ่มได้เลขที่ `N` ใบปรับลดได้ `-N` (`:766`) เขียนผ่านเส้นทางบันทึกเอกสารมาตรฐาน แล้วเติมเลข LOT ลงบรรทัดและเขียนแถว LOT ของเอกสาร เฉพาะบรรทัดที่มี LOT (`saveAdjustDoc` `:200-237`) จึง 2045 ที่ไม่แยก LOT ไม่เขียนแถว LOT
8. **เครื่องหมายผูกใบนับ** ทุกใบปรับที่สร้างได้แถวใน [[tbl-ap-ar-trans-detail]] ต่อใบนับหนึ่งใบ (ประเภท 66/68, `billing_no` = เลขที่ใบนับ) ใช้ซ่อนใบนับที่ปรับแล้วและกันปรับซ้ำ (`:772-782`) แล้วบันทึกแถวใน `logs` (`:784`, `workflow.go:65-75`) `CountedDocs` ในผลคือจำนวนใบนับที่ผูกแล้ว

### กล่อง "สินค้าที่ไม่มีการตรวจนับและมียอดคงเหลือ" (`ProductNotFoundModal`, `:282-461`)
หาสินค้า/คลัง/ที่เก็บที่มียอดคงเหลือแต่ไม่มีในใบนับที่ติ๊ก แล้วออกใบปรับให้เป็น 0 ช่อง **เอกสารวันที่** อ่านอย่างเดียว คือค่า "ถึงวันที่" ของจอหลัก (`:386`, `:916`) **เวลา** (เช่น 23:59 ว่าง = ทั้งวัน `:391`) รายการคลังติ๊กเลือกได้ ค่าเริ่มต้นติ๊กทุกคลัง (`:309-313`) **รายการคลังในกล่องนี้ไม่ถูกกรองตามสิทธิ์คลังของผู้ใช้** เพราะเรียก `useWhShelf()` โดยไม่ส่ง `perm` (`:301`, กรองเฉพาะเมื่อ `perm` เป็นจริง `StockToolBits.tsx:44-49`) ต่างจากจอที่กรองตามสิทธิ์ ดู [[proc-wh-shelf-permission]]
- ปุ่ม **ประมวลผลค้นหา** (`notcountedlist` `:319-338`) ไม่เลือกคลังขึ้น "กรุณาเลือกคลังสินค้าอย่างน้อย 1 คลัง" ส่ง `{dateEnd, docTime, whCodes, docNos}` โดย `docNos` คือใบที่ติ๊กอยู่ในจอหลัก (`:917`) Go รวมยอดคงเหลือต่อสินค้า + คลัง + ที่เก็บ (หน่วยฐาน) ที่ไม่เป็น 0 และไม่มีบรรทัดของใบนับในชุด `docNos` ที่คลัง/ที่เก็บเดียวกัน ถ้าใส่เวลา นับเอกสารจนถึงเวลานั้นของวัน ถ้าว่างนับทั้งวัน (`stock_lot.go:837-866`, เงื่อนไขเวลา `:847-848`)
- ปุ่ม **สร้างเอกสารปรับปรุงเป็น 0** (`notcountedrun` `:340-366`, ปิดเมื่อยังไม่มีรายการ) ยอดบวกออกใบปรับลด ยอดติดลบออกใบปรับเพิ่ม ตั้งราคาจากต้นทุนเฉลี่ยเช่นเดียวกัน วันที่เอกสาร = "ถึงวันที่" เวลาเอกสาร = ช่องเวลา ถ้าว่างใช้ 06:00 (`stock_lot.go:900-979`, เวลา `:960-963`) สำเร็จแล้วปิดกล่อง ขึ้นข้อความผล และโหลดใบนับใหม่ (`:920-925`) ใบปรับชุดนี้ไม่ได้เขียนเครื่องหมายผูกใบนับ
- ข้อสังเกตจากโค้ด (ยังไม่ได้ทดสอบในเบราว์เซอร์): ปุ่มเปิดกล่องใช้ได้แม้ไม่ได้ติ๊กใบนับ (`disabled={busy}` `:889-890`) ถ้า `docNos` ว่าง Go ไม่ตัดสินค้าใดออก (`cleanOptionalDocNos` `:826-835`, `NOT EXISTS ... = ANY($4)` `:850-857`) ทุกยอดคงเหลือในคลังที่เลือกจึงเข้าเงื่อนไข และการสร้างเอกสารจะปรับทั้งหมดเป็น 0 รายการค้นหาและรายการที่ออกใบปรับถูกตัดที่ 2000 แถวแรกเรียงตามรหัสสินค้า (`:865-866`) โดยหน้าจอไม่แจ้งว่าถูกตัด

## 2047 ปรับปรุงมูลค่าสินค้า Lot คงค้าง (`LotAmountAdjustScreen`, `:93-279`)
ปรับ LOT ที่จำนวนคงเหลือเป็น 0 แต่ยังมีมูลค่าเหลือ ให้มูลค่าเป็น 0 ด้วยใบปรับที่ไม่มีจำนวน (จำนวน 0 มีแต่มูลค่า)
- **เงื่อนไข** (`:207-250`): **ณ วันที่** (วันนี้), **สินค้าตั้งแต่ / ถึง** (พิมพ์ตัวพิมพ์ใหญ่ ปุ่มค้นหาเปิดชุดค้นสินค้า `BcLookupModal` ตาราง `ic_inventory` `:260-274` เลือก "ตั้งแต่" แล้วช่อง "ถึง" ว่างจะเติมค่าเดียวกันให้), **รูปแบบ ปรับเพิ่ม** (IA) และ **รูปแบบ ปรับลด** (IS) ต่างจาก 2045/2046 ตรงที่ไม่เลือกรูปแบบแรกให้ ค่าตั้งต้นคือ "(ตามค่าเริ่มต้น)" (`StockToolBits.tsx:62`)
- **โหลด** ตอนเปิดจอและเมื่อกดปุ่ม **โหลดข้อมูล** (`lotamountload` `:117-133`) ตารางตรวจ: รหัสสินค้า, ชื่อสินค้า, หน่วยนับ, คลัง, ที่เก็บ, LOT, จำนวนคงเหลือ, มูลค่าคงเหลือ (`LOT_COLS` `:30-34`) ติ๊กเลือกรายการได้ ค่าเริ่มต้นติ๊กทั้งหมด ถ้าผลถูกตัดขึ้นสีแดง "แสดงเพียงบางส่วน กรุณาจำกัดช่วงรหัสสินค้าให้แคบลง" (`:256`) ว่างขึ้น "ไม่พบ LOT ที่มีมูลค่าคงเหลือค้าง" รายการซ้ายแค่เลือกแถวเพื่อดู ไม่เปลี่ยนการติ๊ก (`:181`)
- Go หา LOT จาก [[tbl-ic-trans-detail-lot]]: รวม `calc_flag x qty` และ `calc_flag x amount` ต่อ สินค้า + คลัง + ที่เก็บ + LOT สำหรับเอกสารที่วันที่ไม่เกิน "ณ วันที่" เอาเฉพาะกลุ่มที่จำนวนรวมเป็น 0 และมูลค่ารวม (ปัด 2 ตำแหน่ง) ไม่เป็น 0 ในช่วงรหัสสินค้าที่กรอก (`stock_lot.go:313-324`) ส่งกลับสูงสุด 5000 แถว เกินแล้วตั้งธง `truncated` (`:347-365`)
- ปุ่ม **ปรับปรุงมูลค่า** (Ctrl+S ผูก `useShortcuts(ask, null, true)` `:153`; ปิดเมื่อไม่ได้ติ๊กรายการ `:200`) ถามยืนยัน "ต้องการปรับปรุงมูลค่าคงเหลือ ของสินค้าหรือไม่" (`:276`) ส่ง `lotamountsave` ด้วยเงื่อนไข + กุญแจ (สินค้า/คลัง/ที่เก็บ/LOT) ของรายการที่ติ๊ก และรูปแบบเลขที่ IA/IS (`:134-146`) ฝั่ง Go รันในธุรกรรมเดียวพร้อม advisory lock (`stock_lot.go:400-401`) **อ่านรายการค้างใหม่จากฐานข้อมูลอีกรอบ** แล้วจับคู่กับกุญแจที่ติ๊ก (`:404-412`) แถวที่ติ๊กไว้แต่ไม่ค้างแล้วนับเป็น `ข้าม N รายการ` (`:423`) มูลค่าคงเหลือเป็นบวก = ออกใบปรับลด (68) มูลค่าติดลบ = ออกใบปรับเพิ่ม (66) บรรทัดมีจำนวน 0 ราคา 0 และมูลค่าเท่ากับค่าสัมบูรณ์ของมูลค่าที่ค้าง (`:413-421`) เลขที่ใบเพิ่ม `N` ใบลด `-N` วันที่เอกสาร = "ณ วันที่" เวลา 23:59 (`:440-454`) ใบปรับเขียนแถว LOT ของตัวเองที่ล้างมูลค่า จึงกดซ้ำแล้วไม่เหลือรายการ (`:384-386`, `saveAdjustDoc` `:224-235`) แล้วบันทึก `logs` (`:456`) จอขึ้นข้อความผลและโหลดใหม่

## ข้อควรระวัง
- เอกสารที่สร้างเป็นเอกสารจริง (66/68) ย้อนด้วยการยกเลิกเอกสาร ไม่มีปุ่ม "ย้อนการปรับ" ในจอ ดู [[proc-doc-cancel-approve]]
- ถ้าติ๊กใบนับเกิน 200 ใบ ตารางรายการล่างจะไม่อัปเดต (หน้าจอไม่แสดงข้อผิดพลาดของ `lotautocheck` `:593-596`) และการประมวลผลจะขึ้นข้อความ "เลือกเอกสารตรวจนับ 1-200 ใบ" (`stock_lot.go:544-546`)
- ใบนับที่คืนมาจาก Go มีสูงสุด 2001 ใบ และหน้าจอไม่แจ้งเมื่อถูกตัด (`stock_lot.go:502`)
- การประมวลผลปรับทั้งแถวที่ไม่ได้นับ ในชุดไขว้ สินค้า x คลัง x ที่เก็บ ของใบนับให้เป็น 0 (ข้อ 5 ด้านบน) ถ้านับสินค้าบางรายการในคลังหนึ่งและสินค้าอีกชุดในอีกคลัง ยอดของสินค้าชุดแรกในคลังหลังก็เข้าข่ายถูกปรับเป็น 0 ด้วย ตรวจรายการด้วยปุ่มตารางล่างก่อนประมวลผล
- ไม่มีคีย์ Esc ในทั้งสามจอ (`useShortcuts(ask, null, true)` ไม่ส่งตัวยกเลิก `ScreenFrame.tsx:50-53`)
