# ข้อมูลสินค้าเพิ่มเติม (ItemDetail2Screen)

จอแก้ข้อมูลสินค้า "ส่วนที่เหลือ" ที่ไม่อยู่ในจอ [[scr-item-master]]: ยี่ห้อ/กลุ่ม/มิติ 45 ช่อง, ชื่อการตลาด/ชื่อ POS/ชื่อพิมพ์บิล, คลังประจำ, สถานะควบคุม, สินค้าทดแทน/พ่วง/แนะนำ ฯลฯ รวม 16 ส่วน (`TABS`, `:64-68`) ซึ่งเรียงต่อกันในหน้าเดียวเป็นกล่อง "ส่วนที่ N" พร้อมแถบ "ไปที่ส่วน:" ไม่ได้แยกเป็นแท็บให้สลับ (`:618-637`, `:797-814`) แก้ได้อย่างเดียว (เพิ่มสินค้าใหม่หรือลบไม่ได้ ต้องไปที่ข้อมูลสินค้า) โหลดและบันทึกทั้งหมดผ่านชุดเดียวที่ฝั่ง Go (`/api/process/itemdetail/get|save`, `itemdetail_handler.go:14-27`; get ใช้สิทธิ์อ่าน save ใช้สิทธิ์เขียน `permission.go:31,42`) หน้าจอทำหน้าที่แสดงผล รับค่า และเรียก API ส่วน Go ตรวจรหัสและบันทึกทั้งชุดในธุรกรรมเดียว (`item_detail.go:20-21`, `:397-435`) ตรรกะฝั่งเซิร์ฟเวอร์ดู [[proc-item-master-detail]]

เมนู: สินค้า > ทะเบียนข้อมูลสินค้าและคลังที่เก็บ > ข้อมูลสินค้าเพิ่มเติม (`bcMenu.json:1952`) ไม่จำกัดเฉพาะผู้ดูแลระบบ

## โครงจอ
- ซ้าย: ปุ่มสลับ "มุมมองรายการ:" **ตามรหัสสินค้า** / **ตามบาร์โค้ด (ทุกหน่วย)** (`:653-694`; สลับแล้วล้าง SQL ที่ผู้ใช้ปรับเองของมุมมองเดิม) ใต้ลงมาเป็นรายการสินค้า (อ่านอย่างเดียว) ดึง 500 แถวแรกจากการค้นหา (`queryLimit(..., 500)`, `:358`) ตามรหัสค้นจากรหัส/ชื่อ/หน่วยมาตรฐาน ตามบาร์โค้ดค้นจากบาร์โค้ด/รหัส/คำอธิบาย/ชื่อ (`:347`) คอลัมน์ตามรหัส: รหัสสินค้า, ชื่อสินค้า, หน่วยนับ; ตามบาร์โค้ด: บาร์โค้ด, รหัสสินค้า, ชื่อสินค้า, หน่วย (`:639-641`) คำสั่งค้นดึงยอดคงเหลือและต้นทุนเฉลี่ย (หรือราคาของบาร์โค้ด) มาด้วยแต่ไม่มีคอลัมน์แสดง (`:349-351`) สินค้าประเภท "สูตรสี" (`item_type` 5) แสดงตัวอักษรสีน้ำเงิน (`:193`, `:642`) กดสองครั้งที่แถว = เปิดแล้วเข้าโหมดแก้ไขทันที (`:706`; ต้องมีสิทธิ์แก้ไข `BcDataList.tsx:143-148`) เปิดจอแล้วโหลดแถวแรกให้อัตโนมัติ (`:364-366`) ปรับ SQL ของรายการได้ผ่านกลไก DataList (`listKey`, `defaultSql`, `:700-703`) ดูกลไกที่ [[scr-data-list-and-lookup]]
- ขวา: แถบสถานะ "บันทึกล่าสุด <เวลา>", "แก้ไขแล้ว N ช่อง", ป้าย "โหมดดูข้อมูล"/"โหมดแก้ไข" (`:720-727`) ใต้ลงมาเป็นช่อง **ค้นหาบาร์โค้ด** (พิมพ์แล้ว Enter หรือกดปุ่ม ค้นหา `:754-757`; Go หารหัสสินค้าจากบาร์โค้ดแรกที่ตรง ไม่พบขึ้น "ไม่พบบาร์โค้ด <ค่า>" `item_detail.go:196-200`) และปุ่ม **รูปภาพสินค้า (N)** (ปิดไว้ถ้าสินค้าไม่มีรูป `:762`; N นับจากตาราง `images` ที่ `image_id` ตรงรหัสสินค้า `item_detail.go:190`; เปิดเป็นแกลเลอรีอ่านอย่างเดียว `:789` จำนวนสูงสุดต่อสินค้ารับจากเซิร์ฟเวอร์ ถ้าไม่มีค่าใช้ 6 `:333,:379`) ตัวจัดการรูปเต็มดู [[scr-item-pictures]]
- การ์ดหัวสินค้า `HeaderCard` (`:199-228`, ใช้ที่ `:796`) อ่านอย่างเดียว ทุกช่องปิดไว้ แสดงค่าที่แก้ในจอ [[scr-item-master]]: รหัสสินค้า, สินค้ามี Serial, ประเภทภาษี, ประเภทสินค้า, ชื่อสินค้า 1-2, ชื่อสินค้า (อังกฤษ) 1-2, ประเภทหน่วยนับ, ต้นทุนต่อหน่วย, หน่วยนับมาตรฐาน, ประเภทต้นทุน, ประเภทรายได้, รูปแบบสินค้า, ผู้จำหน่าย, รหัสเครื่องหมาย, รหัสบัญชี 1-4, กว้าง x ยาว x สูง, น้ำหนัก, แก้ไขรายละเอียดได้, แก้ไขราคาได้, ผู้ผลิต, สะสมแต้ม, เครื่องดื่ม, ใช้วันหมดอายุ (`:203-210`) ช่อง "แก้ไขรายละเอียดได้" คือค่า `update_detail` ที่กำหนดว่าสินค้านี้แก้จากจอนี้ได้หรือไม่ (ดูหัวข้อ การโหลดและบันทึก)
- ใต้การ์ดคือแถบ "ไปที่ส่วน:" มีปุ่มชื่อส่วนทั้ง 16 ส่วน กดแล้วเลื่อนไปที่กล่องนั้น (`:797-814`) ตามด้วยกล่องของแต่ละส่วนเรียงต่อกัน หัวกล่องมีสีต่างกัน (`SECTION_THEMES`, `:609-637`) ป้าย "ส่วนที่ N" นับ 1-16 ต่อเนื่อง (`:626`) ส่วน A-G จึงเป็นส่วนที่ 10-16
- ปุ่ม (`:729-751`): โหมดดู = **แก้ไข** (ต้องมีสิทธิ์แก้) และ **ปิดหน้าจอ**; โหมดแก้ = **บันทึก** (กดได้เมื่อมีการเปลี่ยนแปลงเท่านั้น `disabled={!dirty}`) และ **ปิดหน้าจอ** (จริงๆ คือ ยกเลิกการแก้ไข คืนค่าเดิม `cancel`, `:428`)
- คีย์ลัด: **Ctrl+S** บันทึก, **Esc** ยกเลิกการแก้ไข (ผูกที่ `useShortcuts` `:451` ทำงานเฉพาะขณะอยู่โหมดแก้ไข และเมื่อแท็บนี้แสดงอยู่ `ScreenFrame.tsx:37-58`), **Ctrl+B** ไปช่องค้นหาบาร์โค้ด (`:838-852`)

## การโหลดและบันทึก
- เลือกสินค้าจากรายการหรือค้นบาร์โค้ด: ส่ง `POST /api/process/itemdetail/get` ด้วยรหัสหรือบาร์โค้ด แล้วแสดงข้อมูลทั้งชุดในโหมดดู (`load`, `:410-418`) ถ้ากำลังแก้ไขค้างและมีการเปลี่ยนแปลง ขึ้นเตือน "มีข้อมูลที่ยังไม่บันทึก กรุณาบันทึกหรือยกเลิกก่อนเปลี่ยนรายการ" (`:411`)
- ปุ่ม **แก้ไข** (`startEdit`, `:420-426`): ต้องมีสิทธิ์แก้; Go ตอบ `editable = true` เฉพาะสินค้าที่ `ic_inventory.update_detail = 1` (`item_detail.go:208`; ตรงกับช่อง "แก้ไขรายละเอียดได้" ในการ์ดหัวสินค้า) ถ้าไม่ใช่ขึ้น "สินค้านี้ยังไม่พร้อมแก้ไข  จึงแก้ข้อมูลเพิ่มเติมไม่ได้" (`:423`) การกดสองครั้งที่แถวในรายการ **ข้ามการตรวจนี้** (`:706` เรียก `setIsEditing(true)` ตรงๆ) จึงเข้าโหมดแก้ไขได้ แต่ตอนบันทึก Go ปฏิเสธด้วย "สินค้านี้ยังไม่พร้อมแก้ไข  จึงบันทึกข้อมูลเพิ่มเติมไม่ได้" (`item_detail.go:406-408`)
- **บันทึก** (`save`, `:430-449`): ไม่มีสิทธิ์ขึ้น `คุณไม่มีสิทธิ์ "แก้ไขข้อมูล" ในหน้าจอนี้ ...`; ส่ง `POST /api/process/itemdetail/save` ก้อนเดียวพร้อม `item`, `detail` และตาราง 11 ชุด (market, short, pos, billing, colors, sizes, patterns, replace, bundle, suggest, manufacturers) สำเร็จขึ้น "บันทึกข้อมูลสินค้าเพิ่มเติมแล้ว" และรีโหลดค่าจากเซิร์ฟเวอร์
- ฝั่ง Go ตรวจทุกตารางย่อยก่อนแตะฐานข้อมูล: ข้ามแถวว่าง, สถานะต้องเป็น 0 หรือ 1, จำนวนต้องเป็นเลขไม่ติดลบ, ไม่เกิน 500 แถวต่อตาราง, รหัสสี/ขนาด/รูปแบบ/ผู้ผลิตห้ามซ้ำกันเองในตาราง (`cleanRows`, `item_detail.go:266-300`) รหัสที่ไม่มีในตารางหลักถูกปฏิเสธด้วย "ไม่พบ : <ชนิด> <รหัส>" (`:353`, `:475`, `:480`) แล้วทำงานทั้งหมดในธุรกรรมเดียว: ล็อกแถวสินค้า (`FOR UPDATE`), เพิ่มแถว `ic_inventory_detail` ถ้ายังไม่มี (ยกเว้นสินค้าประเภท 5), `UPDATE` เฉพาะฟิลด์ที่ส่งมา และลบแล้วเพิ่มใหม่ทุกตารางย่อย (`:397-435`, `:462-557`)
- รูปภาพโหลดตามต้องการผ่าน `POST /api/process/itempicture/get` (`kind: "item"`, `loadPictures` `:372-381`)

## ตารางที่เกี่ยวข้อง
[[tbl-ic-inventory]], [[tbl-ic-inventory-detail]], [[tbl-ic-inventory-barcode]], [[tbl-ic-unit-use]], [[tbl-ic-shelf]], [[tbl-ic-warehouse]], [[tbl-ap-supplier]] ส่วนตารางจอ lookup (`ic_brand`, `ic_pattern`, `ic_design`, `ic_grade`, `ic_model`, `ic_category`, `ic_group`, `ic_class`, `ic_group_sub`, `ic_group_sub2`, `ic_color`, `ic_size`, `ic_dimension`, `erp_user_group`) เป็นตารางรหัสที่อ่านผ่านหน้าต่างค้นหา ตารางย่อยที่ Go เขียน (ยังไม่มีโน้ตตาราง): `ic_name_merket`, `ic_name_billing`, `ic_name_short`, `ic_name_pos`, `ic_color_use`, `ic_size_use`, `ic_pattern_use`, `ic_inventory_replacement`, `ic_inventory_suggest`, `ic_inventory_bundle`, `ic_manufacturer_list` และนับรูปจากตาราง `images`

## ข้อควรระวัง
- ฟอร์มเดียวแต่เก็บ 2 ก้อน (`item` กับ `detail`) ตัวนับ "แก้ไขแล้ว N ช่อง" นับทีละฟิลด์ของสองก้อนนี้ และนับ 1 ต่อหนึ่งตารางย่อย (grid) ที่มีการเปลี่ยน (`:338-343`)
- ช่องมิติ 21-45 ไม่มี lookup เป็นข้อความอิสระ
- การเปลี่ยนรายการที่ยังไม่บันทึกถูกบล็อก ไม่ได้ถามแบบ "ทิ้ง/ทำต่อ" เหมือนจอ [[scr-item-master]]
- สินค้าแนะนำ (ส่วน F) แสดงทั้งแถวที่สินค้านี้เป็นเจ้าของและแถวที่สินค้าอื่นแนะนำสินค้านี้ (`item_detail.go:184-188`) แต่ตอนบันทึก Go ลบทั้งสองทิศ (`ic_suggest_code` หรือ `ic_code` เท่ากับรหัสนี้) แล้วเขียนกลับทิศเดียว (`:532-537`) แถวที่สินค้าอื่นเป็นเจ้าของจึงกลายเป็นแถวของสินค้านี้ หรือหายไปถ้าผู้ใช้ลบออกจากตาราง
- สิทธิ์ตรวจสองชั้น: หน้าจอเช็ก `rights.canEdit` (`:421`, `:432`) และ Go เช็กสิทธิ์เขียนของ `itemdetail/save` (`permission.go:42`) ส่วนเงื่อนไข `update_detail` ตรวจที่ Go ทุกครั้งที่บันทึก (`item_detail.go:406`)
