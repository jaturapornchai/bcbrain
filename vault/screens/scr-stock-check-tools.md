# เครื่องมือตรวจสอบสินค้า ราคา บาร์โค้ด และ Serial

สี่จอเล็กในหมวดสินค้า/คลัง ใช้ตรวจข้อมูลที่ยิงหรือนำเข้า มีสองจอที่ **อ่านอย่างเดียว** (2018 ตรวจบาร์โค้ดจากข้อความ, 2066 วิเคราะห์ Serial) ส่วนจอตรวจราคา (2017) แก้ราคาที่ 1 ของบาร์โค้ด และจอตรวจนับ Serial (2044) สร้างเอกสารนับสต็อก กฎของจอเหล่านี้อยู่ที่ Go `POST /api/process/stocktools/{action}` (`stocktools_handler.go:89-186`) ยกเว้นการค้นของจอ 2017 และรายการเอกสาร/Serial ที่เปิดดูของจอ 2044 ซึ่งเบราว์เซอร์สร้าง SQL เอง ดู [[proc-stock-tools]] และ [[api-proc-actions-stock]]

## 2017 ตรวจสอบราคาสินค้า (`CheckPriceScreen`)
จำลองเครื่องตรวจราคา
- ช่อง **ยิงบาร์โค้ด** รับบาร์โค้ด รหัสสินค้า หรือชื่อสินค้า แล้ว Enter หรือปุ่ม **ค้นหา** / **ตรวจสอบราคา** ค้นแบบมีคำนั้นอยู่ในข้อความ ไม่สนตัวพิมพ์ (`ILIKE '%…%'` บนบาร์โค้ด รหัสสินค้า และคำอธิบายบาร์โค้ดหรือชื่อสินค้า) ผ่าน SQL ที่เบราว์เซอร์สร้างด้วย `queryList` จำกัด 100 แถว เรียงรหัสสินค้าแล้วบาร์โค้ด (`:595-613`) เปิดจอแล้วค้นด้วยคำว่างทันที (`:633-635`) จึงเห็นรายการแรก 100 แถว
- ถ้าค้นได้ แถวแรกของผลถูกเติมเข้าฟอร์มอัตโนมัติ (บาร์โค้ด, รหัส -- ชื่อ (หน่วย), ราคา, ราคาใหม่ = ราคาปัจจุบัน `:618-626`) ถ้าค้นไม่พบฟอร์มคงค่าเดิมและตารางว่าง; คลิกแถวอื่นในตารางเพื่อเลือกบาร์โค้ดนั้นมาที่ฟอร์ม (`:753-760`) ตารางแสดงราคาทั่วไป/ราคาสมาชิก/ราคาที่ 2/ราคาที่ 3 (`:743-746` คำสั่งค้นดึงราคาที่ 4 มาด้วยแต่ไม่แสดง)
- **บันทึก** (ปิดเมื่อไม่มีสิทธิ์แก้ไข `:672`): ไม่เลือกบาร์โค้ดจะไม่ทำอะไร ถามยืนยันด้วยกล่องเบราว์เซอร์ `ต้องการเปลี่ยนราคาเป็น : <ราคา> บาท` (`:645`) แล้ว `POST /api/process/stocktools/checkpricesave` ด้วย `{barcode, newPrice}` สำเร็จขึ้นที่แถบสถานะ `ปรับราคาบาร์โค้ด <บาร์โค้ด> เป็น <ราคา> เรียบร้อยแล้ว` (ผิดพลาดก็แสดงที่แถบสถานะเป็นตัวแดง) และโหลดตารางใหม่ ซึ่งทำให้ฟอร์มกลับไปแสดงแถวแรกของผลค้น (`:637-657`)
- กฎอยู่ที่ Go `CheckPriceSave` (`check_price.go:31-72`): ต้องมีบาร์โค้ด ไม่งั้นขึ้น "กรุณายิง Barcode ก่อน"; ราคาใหม่ต้องเป็นตัวเลขที่ถูกต้อง ปัดตามทศนิยมราคาของบริษัท และต้องมากกว่า 1 ไม่งั้นขึ้น "ราคาใหม่ต้องมากกว่า 1" (`:41-43`); ล็อกแถวแรกของบาร์โค้ดเพื่ออ่านราคาเก่า แล้ว `UPDATE ic_inventory_barcode SET price` ให้ **ทุกแถวที่มีบาร์โค้ดนั้น** (ไม่สนตัวพิมพ์) ในธุรกรรมเดียว ไม่พบบาร์โค้ดขึ้น `ไม่พบบาร์โค้ด <รหัส>` และบันทึกราคาเก่า/ใหม่ลงบันทึกกระบวนการชื่อ "ตรวจสอบราคา" (`:59-69`) จึงแก้ได้เฉพาะ **ราคาที่ 1 (คอลัมน์ `price`)** ของบาร์โค้ด ราคาอื่นและราคาตามกลุ่มลูกค้าแก้ที่ [[scr-modify-price]]
- จอนี้ใช้กรอบจอของไฟล์ `IcExtraScreens` (ไม่มีคีย์ลัด Ctrl+S / Esc) ใช้ปุ่มเท่านั้น

## 2018 ตรวจสอบบาร์โค๊ดจาก Text File (`BarcodeCheckerScreen`)
อ่านอย่างเดียว ไล่บาร์โค้ดที่ป้อนหรือนำเข้าว่ามีอยู่ใน `ic_inventory_barcode` หรือไม่ (ป้าย "ตรวจสอบ (อ่านอย่างเดียว)" `:69`)
- ซ้าย: กล่องข้อความ "บาร์โค้ดที่ต้องการตรวจ (บรรทัดละ 1 ค่า)" นับ `N บาร์โค้ด (สูงสุด 2000)` (`:92-94`) ปุ่ม **นำเข้าไฟล์** (`.txt .csv .tsv` ต่อท้ายข้อความเดิม `:54-59`, `:86`) แต่ละบรรทัดใช้เฉพาะ **คอลัมน์แรก** ที่แบ่งด้วย Tab จุลภาค หรืออัฒภาค (`parseBarcodes`, `:35`) ไม่มีการข้ามบรรทัดหัวตาราง ถ้าไฟล์มีหัวตาราง หัวนั้นจะถูกตรวจเป็นบาร์โค้ดหนึ่งค่า
- ปุ่ม **ตรวจสอบ** (หรือ Ctrl+S `:60`) เรียก `POST /api/process/stocktools/barcodecheck` ด้วย `{barcodes}` ไม่มีข้อมูลขึ้น "กรุณาป้อนหรือนำเข้าบาร์โค้ดก่อน" เกิน 2000 ขึ้น `ตรวจได้ครั้งละไม่เกิน 2000 บาร์โค้ด` (`MAX_BARCODES`, `:23`, `:45-47`)
- Go (`stock_tools.go:104-155`): ตัดช่องว่าง ข้ามบรรทัดว่าง บาร์โค้ดยาวเกิน 50 ตัวอักษรทำให้ทั้งชุดถูกปฏิเสธ ค้นแบบตรงทุกตัว (ไม่ใช่ค้นบางส่วน) จาก `ic_inventory_barcode` เชื่อมชื่อสินค้าจาก `ic_inventory` ถ้าบาร์โค้ดซ้ำในตารางใช้แถวแรกตาม `roworder` ผลเรียงตามลำดับที่ป้อน บาร์โค้ดที่ซ้ำในข้อความก็ซ้ำในผล
- ขวา: ตารางที่พบ (บาร์โค้ด, รหัสสินค้า, ชื่อสินค้า, หน่วยนับ, ราคา 1-4 = คอลัมน์ `price`, `price_2`, `price_3`, `price_4`) และกล่องแดง "ไม่พบในระบบ N รายการ" ลิสต์บาร์โค้ดที่ไม่มี (`:97-103`) ถ้าไม่พบเลยสักค่า ตารางว่างขึ้น "ไม่พบบาร์โค้ดในทะเบียนสินค้า"; ก่อนกดตรวจขึ้น "กด ตรวจสอบ เพื่อดูสินค้าและราคาของบาร์โค้ด"
- **ล้างหน้าจอ** ล้างข้อความและผลลัพธ์ แก้ข้อความแล้วผลเดิมถูกล้างให้ตรวจใหม่ (`:78`, `:93`) ต่างจากจอ EAN13 ใน [[scr-barcode-setup]] (2019) ที่ตรวจความถูกต้องของเลข ส่วนจอนี้ตรวจว่ามีในทะเบียนหรือไม่

## 2044 ตรวจสอบสินค้า Serial Number (`SerialStockCountScreen`)
ยิง Serial ทีละตัวแล้วบันทึกเป็น **เอกสารนับสต็อก 1 ใบ** (`trans_flag = 76`, ประเภทเอกสาร CO `stock_tools.go:425`) ดูเอกสารนี้ที่ [[doc-stock-count]]
- ซ้าย: รายการเอกสารนับสต็อกที่มีอยู่ (วันที่, เลขที่เอกสาร, คลัง, หมายเหตุ) 200 ใบล่าสุดจาก `ic_trans` ที่ `trans_flag = 76` ค้นจากเลขที่/หมายเหตุ/คลัง (`:50-63`) คลิกเอกสารเพื่อดู (อ่านอย่างเดียว) โหลดรายการ Serial ของเอกสารจาก `ic_trans_serial_number` ไม่เกิน 500 แถว (`selectDoc`, `:170-186`) ราคาที่แสดงใช้ราคาที่เก็บไว้ ถ้าไม่มีใช้ต้นทุนเฉลี่ยของสินค้า
- **เพิ่มใหม่** (ปุ่มซ้ายและบนแถบเครื่องมือ ต้องมีสิทธิ์เพิ่ม `:85-89`, `:240`) ล้างฟอร์มเข้าโหมดเพิ่ม ป้ายเหลือง "เพิ่มรายการใหม่" ช่องหัวเอกสาร: เลขที่เอกสาร (ปิดไว้ ออกให้เองเมื่อบันทึก), ประเภทเอกสาร (รูปแบบเลขที่ของประเภท CO จาก `erp_doc_format` ผ่าน `stocktools/formats` `:74`), วันที่, เวลา (5 ตัวอักษร), เลขที่/วันที่อ้างอิง, **คลัง** และ **ที่เก็บ** (ตัวเลือกกรองตามสิทธิ์คลัง/ที่เก็บของผู้ใช้ ดู [[proc-wh-shelf-permission]]; เปลี่ยนคลังจะล้างที่เก็บ `:260`), หมายเหตุ, มูลค่ารวม (อ่านอย่างเดียว) (`:252-273`)
- ช่อง **Serial Number** ตัวพิมพ์ใหญ่ ยิง/พิมพ์แล้ว Enter หรือปุ่ม **เพิ่ม Serial** (`:276-282`) เรียก `serialscan` ได้สินค้า/หน่วยนับ/ราคา: ซ้ำในรายการขึ้น `มีการป้อน Serial Number <รหัส> ไปแล้ว`, ไม่พบขึ้น `ไม่พบ Serial Number <รหัส> ในทะเบียน Serial` (`:92-107`) Go ค้นจากทะเบียน Serial เชื่อมสินค้าและหน่วยนับ ราคาเริ่มต้นคือต้นทุนเฉลี่ยของสินค้า (`serialLookupSQL`, `stock_tools.go:270-300`) ติ๊ก Auto Focus เพื่อให้เคอร์เซอร์กลับช่องสแกนทุกครั้ง; ลิงก์ "ลบรายการล่าสุด" ถอดตัวสุดท้าย (`:294-296`) ดู [[tbl-ic-serial]]
- ตาราง: หมายเลขเครื่อง, รหัสสินค้า, ชื่อสินค้า, หน่วยนับ, ราคาซื้อ/ขาย (แก้ได้ขณะเพิ่ม ราคา 0 แสดงเป็นว่าง `:104`, `:118-144`)
- **บันทึก** (Ctrl+S; Esc ยกเลิก `:166`) ตรวจฝั่งหน้าจอตามลำดับ: สิทธิ์ "เพิ่มข้อมูลใหม่", "กรุณาเลือกคลังและที่เก็บ", "ยังไม่มี Serial Number ในรายการ" (`:148-150`) แล้ว `POST /api/process/stocktools/serialcountsave` ส่งหัว + รายการ Serial + ราคาต่อ Serial (ไม่ส่งเลขที่เอกสาร `:152-157`) สำเร็จขึ้น `บันทึกเอกสารนับสต็อก <เลขที่> แล้ว (N สินค้า, M Serial)` (`:164`) ดู [[tbl-ic-trans]] และ [[tbl-ic-trans-serial-number]]
- Go `SerialCountSave` (`stock_tools.go:354-479`) ทำในธุรกรรมเดียว: ตรวจวันที่รูปแบบ ปี-เดือน-วัน, Serial 1-5000 ตัว ห้ามว่างหรือซ้ำ (ไม่สนตัวพิมพ์), คลัง/ที่เก็บต้องมีใน `ic_shelf` ("ไม่พบคลัง/ที่เก็บ X/Y"), ทุก Serial ต้องมีในทะเบียนและมีหน่วยนับ จากนั้นรวมเป็นบรรทัดเดียวต่อสินค้า (จำนวน = จำนวน Serial ราคา = ราคาของ Serial ตัวแรกของสินค้านั้น `groupSerialLines`, `:332-345`) ออกเลขที่ตามประเภท CO ถ้าไม่ระบุ บันทึกหัว/รายการ แล้วใส่ `ic_trans_serial_number` หนึ่งแถวต่อ Serial (`calc_flag` 1) และบันทึกกระบวนการ "ตรวจนับสินค้า Serial Number" ถ้าส่งเลขที่เอกสารเดิมมาจะแทนที่เอกสารนั้น (`:351-353`) แต่หน้าจอไม่เคยส่งเลขที่ จึงได้เอกสารใหม่ทุกครั้งที่บันทึก
- ไม่มีปุ่ม แก้ไข/ลบ ของเอกสารที่บันทึกแล้ว: เอกสารเก่าดูได้อย่างเดียว

## 2066 ตรวจสอบ Serial มีปัญหา (`SerialAnalyzeScreen`)
อ่านอย่างเดียว หา Serial ที่ประวัติรับ/จ่ายผิดลำดับ
- ช่อง "รหัสสินค้า" (ว่าง = ทุกสินค้า) ปุ่ม **วิเคราะห์** หรือ Ctrl+S เรียก `POST /api/process/stocktools/serialanalyze` **เปิดจอแล้ววิเคราะห์ทันที** ทุกสินค้า (`useEffect`, `:125-129`)
- Go (`analyzeSerialMoves`, `stock_tools.go:182-251`) เดินประวัติของแต่ละคู่ สินค้า + Serial จาก `ic_trans_serial_number` ของเอกสารที่ `last_status` เป็น 0 (ไม่นับเอกสาร `trans_flag` 144 และ 76) เรียงตามวันที่/เวลา: รายการรับเข้า (`calc_flag` 1) จำคลัง/ที่เก็บล่าสุด รายการออก (`calc_flag` -1) ที่ยังไม่เคยรับเข้า ขึ้น "ออกก่อนรับเข้า (ไม่มีรายการรับเข้ามาก่อน)" และที่ออกจากคลัง/ที่เก็บคนละที่กับรับเข้าล่าสุด ขึ้น "รายการออกจากคลัง/ที่เก็บ X/Y ไม่ตรงกับรายการรับเข้าล่าสุด A/B" รายงานปัญหาแรกของแต่ละ Serial เท่านั้น และคืนไม่เกิน 5000 รายการ
- ผล: แถบ `ตรวจ N Serial พบปัญหา M รายการ` และตาราง รหัสสินค้า, Serial Number, ปัญหาที่พบ, เลขที่เอกสารที่ผิด (`:139`, `SERIAL_COLS` `:29-32`) ว่างขึ้น "ไม่พบ Serial ที่ประวัติผิดปกติ" ข้อความ "ปัญหาที่พบ" มาจากเซิร์ฟเวอร์ ตรรกะ Serial ดู [[term-lot-serial-expire]]
- จอนี้ไม่มีปุ่มแก้ไขข้อมูล แสดงผลอย่างเดียว

## ข้อควรระวัง
- จอ 2044 รวมมูลค่ารวมบนหน้าจอโดยบวกราคาของทุก Serial ด้วยตัวเลขของเบราว์เซอร์ (`Number(s.price)`, `:109-116`) ต่างจากแนวคิดเงินเป็นสตริงใน [[fe-numeric-money]] และอาจไม่ตรงกับยอดเอกสาร เพราะ Go คิดยอดบรรทัดจาก จำนวน x ราคาของ Serial ตัวแรกของสินค้านั้น (`stock_tools.go:435-441`) ถ้า Serial ของสินค้าเดียวกันถูกแก้ราคาไม่เท่ากัน ยอดสองแบบจะต่างกัน
- 2017 ไม่มีโหมดแก้ไข/ยกเลิก: กดบันทึกแล้วยืนยันหนึ่งครั้ง ราคาในฐานข้อมูลเปลี่ยนทันที (ราคาเดิมอยู่ในบันทึกกระบวนการเท่านั้น) และเปลี่ยนทุกแถวที่มีบาร์โค้ดเดียวกัน
- 2018 และ 2066 ไม่เขียนข้อมูลเลย; 2018 ค้นตรงทุกตัวอักษร ส่วน 2017 ค้นบางส่วน
- สถานะ "บันทึกล่าสุด <เลขที่>" ของจอ 2044 ขึ้นเมื่อเปิดดูเอกสารเก่าด้วย ไม่ได้แปลว่าเพิ่งบันทึก (`:173`, `:224`)
